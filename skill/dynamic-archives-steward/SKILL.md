# 动态档案管家（全局版）

> 从「渠道档案管家」抽象而来的通用方法论，适用于任何需要**多系统汇聚 + 定期刷新 + 字段血缘 + AI 摘要**的动态档案表场景。
- **铁律AO 十维审核框架**：本技能的关键判断须覆盖十维中至少与技能域相关的维度（形式/内容/结构/关联/可验证），不得仅凭单一维度下结论。
- **铁律AG 数据+凭证双中枢**：本技能的输入数据须标注来源权威层级，优先使用 Data-全局数据仓库（双中枢）而非未经校验的外部 API 缓存。


## 触发词

动态档案、档案表管理、数据血缘、字段刷新、AI 摘要、档案管家、archives steward、dynamic archive

## 适用场景

- 客户档案表（CRM + ERP + 人工）
- 供应商档案表（ERP + 质量系统 + 人工）
- 项目档案表（多数据源 + 状态跟踪）
- 任何需要定期刷新、字段来源可溯源、AI 生成摘要的在线表格

## 核心架构（四区模型）

| 分区 | 列范围 | 字段类型 | 颜色 | 示例 |
|:--|:--|:--|:--|:--|
| A 区 | 0-N | 人工档案 | 白色 | 名称、对接人、城市、背景 |
| B 区 | N+1 ~ M | 系统 A | 淡蓝 | ERP 出货、售后、终端 |
| C 区 | M+1 ~ P | 系统 B | 淡绿 | CRM 跟进、客户、商机 |
| D 区 | P+1 ~ 末尾 | 分析定级 | 淡橙 | 系统评分、风险标签、差异标记 |

> 实际列号与字段名由项目 `column_index.py` / `column_config.py` 定义。

## 安全规范

1. **禁止 Bash `$(cat file)` 传 JSON**：使用 Python `subprocess.run([...], --args json_str)`
2. **禁止 CSV+split('\n') 读多行文本**：使用 `return_csv: False` + cells 解析
3. **批量写入后必须清理尾部空行**：`clean_trailing_rows(data_end_row)`
4. **任何 set_range_value 后必须抽样验证**：≥3 不连续行
5. **本地缓存必须带 `_meta` / `scan_time`**：过期或无时间戳视为无效

## 变更校验与交叉验证（通用框架）

> 任何新增/修改/删除操作后，必须执行三层校验，防止"血缘断裂→级联未更新→脏数据残留"。

### 三层校验

| 层级 | 核心问题 | 通用校验项 |
|:--|:--|:--|
| **结构层** | 行号、列号、索引、尾部清理是否对 | 行号权威源、列布局一致、无硬编码列号、无已删字段引用、尾部清理、写入回读 |
| **数据层** | 三方数据是否一致、残留是否清零 | 在线表 vs 本地缓存 vs 源系统金额/记录数、覆盖写、缓存时效、数据范围 |
| **业务层** | 口径、联动、合并、评分是否矛盾 | 字段联动（A/B/C → D 区）、风险标签、合并规则、时间窗口、特殊实体规则 |

### 三类变更场景

#### 新增实体
1. 实体名称标准化：括号、城市后缀、全角空格、不可见字符
2. 行号实时重读：禁止用本地列表索引假设行号
3. 映射表更新：名称→ID、集团合并、客户简称词库
4. 分母变化：评分、排名、分级需要全量重算
5. 缓存刷新：新增实体后必须先刷新相关缓存
6. 自动化名单：定时任务名单/范围需更新

#### 修改字段/列/口径
1. A 区人工字段 → 必须重算 D 区评分/差异
2. B/C 区系统字段 → 必须重算 D 区风险标签/评分/差异
3. 列布局变更 → 执行硬编码列号扫描、字段引用扫描、列布局联动检查
4. 口径变化（含税/时间窗口/分类规则）→ 必须全量重跑历史数据，禁止新旧口径混比
5. 风险标签阈值 → 必须在评分引擎中统一配置并全量刷新
6. 合并/分化规则 → 必须重跑所有依赖该规则的脚本

#### 删除/归档实体
1. 缓存清理：删除本地缓存中的旧记录
2. 数据清零：被删除/合并的实体字段必须写 0/空串，禁止残留
3. 合并/分化规则：明确哪些实体合并、哪些分化，并全量重跑
4. 尾部清理：删除行后立即清理尾部空行
5. 报告口径：报告标题、总数、统计口径同步更新
6. 自动化名单：移除已归档实体，防止定时任务仍扫描

### 通用校验清单

| # | 检查项 | 触发时机 | 失败处理 |
|:--|:--|:--|:--|
| 1 | 行号权威源与在线表一致 | 写入前 | 停止，重读 |
| 2 | 列配置与在线表头一致 | 列变更后 | 停止，修正 |
| 3 | 无硬编码列号 | 列变更后 | 停止，改为 COL 常量 |
| 4 | 无已删除字段引用 | 字段重命名后 | 停止，修正 |
| 5 | 尾部清理已执行 | 每次写入后 | 重新执行 |
| 6 | 多行文本安全读取 | 读取时 | 改为 cells 解析 |
| 7 | 写入后抽样回读 | 每次写入后 | 标记异常行 |
| 8 | 实体总数一致 | 刷新前后 | 核对差异 |
| 9 | 关键金额与源系统一致 | 系统刷新后 | 定位差异 |
| 10 | 关键记录数与源系统一致 | 系统刷新后 | 定位差异 |
| 11 | 下游计算列与上游字段联动 | 任何字段修改后 | 重算下游 |
| 12 | 合并规则已应用 | 刷新后 | 重跑 |
| 13 | 缓存未过期 | 刷新前 | 重拉 |
| 14 | 所有写入脚本覆盖旧值 | 代码审查 | 重写 |
| 15 | 时间窗口一致 | 相关脚本后 | 修正 |
| 16 | 风险标签阈值一致 | 标签变更后 | 统一配置 |
| 17 | 报告版本/标题/时间戳一致 | 报告构建后 | 修正 |

### 隐藏风险场景（前置审计必须覆盖）

1. **结构漂移**：插列/删列后硬编码列号未改
2. **语义漂移**：列名没变但口径变化（含税/时间窗口/分类规则）
3. **数据范围错误**：源系统被截断、只拉近期数据、趋势窗口变化
4. **合并/分化规则**：合并规则变更后未全量重跑，旧数据残留
5. **执行顺序错误**：依赖列未生成就先算下游
6. **格式/编码问题**：全角空格、emoji、NUMBER/日期类型读取错误
7. **缓存/状态问题**：过期缓存、损坏 JSON、下游读上游旧缓存
8. **API/系统边界**：字段位置变化、内容截断、API 限流、分页
9. **人工干预**：手动改字段/删行/插行后脚本未重读行号
10. **下游产物**：报告版本/标题/时间戳与刷新记录不一致
11. **时间/日期边界**：跨年度归属、最近日期未更新、时区、格式不一致
12. **聚合口径**：退货/退款/赠品/样品是否剔除、重复统计、分类口径变化
13. **上游数据质量**：源系统录入错误、重复记录、状态变化、负责人变更
14. **身份识别**：企业并购/分立/改名、集团内部交易、新主体未建档
15. **API/执行时异常**：限流未重试、分页截断、部分成功、并发冲突、Token 过期
16. **数值精度**：浮点误差、单位换算、中间四舍五入、除零
17. **AI/LLM 生成**：基于旧数据、幻觉、截断、可重复性、误判
18. **报告与下游产物**：缓存未刷新、图表与表格不一致、版本未更新、脱敏不一致
19. **权限与协作**：多用户并发、自动化与人工重叠、权限不足
20. **备份与可恢复性**：无快照、历史版本未保留、恢复流程未验证
21. **依赖与环境**：包版本、Node 版本、路径分隔符、环境变量、日志缺失
22. **校验脚本盲区**：规则与脚本不同步、误报、未运行、结果未保存

## 盲区与自审（v1.1 补·2026-09-08·技能自进化起点·反模式#45）

- **盲区声明**：动态档案表管理（前置审计/数据血缘/字段来源）依赖字段来源标注的完整性——引用关系未标注/字段来源跨文件时·"数据血缘"断言可能基于不完整证据（假血缘）；校验脚本（validate_channel_archives 三层）与规则不同步时·误报或未运行致校验结果不可信（L22 校验脚本盲区）。
- **实证判例入段**：①**字段来源漂移**（2026-09-02 判例）——档案表字段来源标注缺失时·后续刷新无法判定字段真源·"已标注"假闭环→修法=字段来源强制标注+刷新前核对 ②**校验脚本与规则不同步**（L22 自承）——规则改了校验脚本未跟·误报或未运行·三层校验（结构/数据/业务）须与规则版本对齐。
- **自进化闭环**：档案表管理/校验实战暴露盲区 → 补本段 + 规则/校验增强 → 版本升级 → skill_self_evolution_check 验证。
