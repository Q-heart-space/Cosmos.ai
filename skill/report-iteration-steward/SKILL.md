# 报告迭代管家（通用版）

> **注意**：本技能是通用骨架。项目使用时，应创建项目级技能引用本技能并注入项目参数。
> 项目级示例见 `.workbuddy/skills/apq-report-iteration-steward/SKILL.md`。
- **AI空间（Q博士 治理空间概念）**：本技能运行于 Q博士 治理空间（第三空间）内，输出须遵循跨空间本体论五通道（Harvest-Internal/Harvest-External/Distribute-Internal/Distribute-External/Consistency）语义约束；跨空间输出须标注 space_scope。
- **铁律AN 状态断言前置审查**：技能在输出"未找到""不存在""无变化"等否定/肯定断言前，须执行取证三问（查源→交叉验证→证据锚定）。
- **铁律AG 数据+凭证双中枢**：本技能的输入数据须标注来源权威层级，优先使用 Data-全局数据仓库（双中枢）而非未经校验的外部 API 缓存。


## 适用报告类型

- 任何依赖多源数据的静态 HTML/MD 报告
- 多模块、多图表、需要迭代升级的综合性报告
- 新增分析维度/图表/模块前的预检

**不适用**：单源数据的一次性分析、非结构化报告、实时看板

## 执行流程（7 步）

### Step 0: 模型检查

🛑 **代码/批量写入/全量刷新必须用 deepseek**，否则立即停止。
仅做文本计划、审计、版式审查可不限模型。

### Step 1: 数据可行性预检

**目标**：在动手写计划前，先确认数据靠得住。

| 检查项 | 通过标准 | 失败处理 |
|:--|:--|:--|
| 外部 API 可连通 | 至少 1 次成功查询 | 标记风险，写入 Fallback |
| 关键文件存在 | 文件非空、行数 ≥100 | **停止**，要求先拉取 |
| 数据日期差异 | max-min ≤3 天 | 标注滞后，>7 天必须重拉 |
| 字段填充率 | 关键字段缺失 <50% | 调整图表方案，不硬画空图 |
| 🆕 外部数据实体名匹配 | 新增外部数据源（调查/问卷/第三方）的实体名与报告主体归档名称匹配率 ≥80% | <80%：必须生成名称映射表，手动确认模糊匹配；禁止在报告中混用两种名称体系 |

**输出**：预检结果（哪个字段可行、哪个不可行、Fallback 是什么）

### 🆕 Step 1.5: 新增内容业务逻辑放置评估（V5.3 固化）

**目标**：在动手插入新内容前，先判断放在报告的哪个位置最符合业务逻辑，**禁止默认放末尾**。

#### 三段式内容分类法

将报告中的所有子模块按其认知功能分为三类：

| 类型 | 功能 | 位置规则 |
|:--|:--|:--|
| **分析层**（Analysis） | 客观数据呈现，回答"发生了什么" | 靠前，为后续判断提供事实基础 |
| **洞察层**（Synthesis） | 多源交叉解读，回答"为什么发生" | 居中，连接分析事实与行动方案 |
| **行动层**（Action） | 分级行动+管理层决策，回答"做什么" | 靠后，基于前面的全部输入 |

#### 放置决策流程

```
1. 对新增内容分类：分析层 / 洞察层 / 行动层？
2. 确定该层在报告中的位置区间：
   - 分析层 → 该模块前半段
   - 洞察层 → 该模块中段
   - 行动层 → 该模块末尾
3. 检查放置后是否破坏上下游逻辑链：
   - 分析必须在被引用的洞察之前
   - 洞察必须在依赖它的行动之前
   - 行动/决策不得出现在分析之前
4. 确定插入点后，执行编号连续性检查（Step 3）
```

#### 典型反例（V5.3 教训）

| ❌ 错误做法 | 问题 | ✅ 正确做法 |
|:--|:--|:--|
| 渠道调查洞察放在 6-F 决策清单之后 | 调查洞察（洞察层）被放在行动层之后，逻辑倒挂 | 洞察层应放在分析层之后、行动层之前（6-E 位置） |
| 新增内容默认追加到模块末尾 | 不考虑洞察→行动的前后逻辑 | 先分类，再定位，再插入 |

**输出**：新内容的类型分类 + 推荐插入位置 + 放置后的上下游逻辑验证。

#### 模板

```
新增内容：[描述]
内容类型：分析层 / 洞察层 / 行动层
推荐位置：[模块X-Y 之后 / 模块X-Z 之前]
逻辑验证：
  - 上游依赖：[哪些模块的结论被本内容引用]
  - 下游消费者：[哪些模块依赖本内容的结论]
  - 放置后逻辑链是否完整：[是/否·说明]
编号影响：插入后序列为 [X-A→X-B→X-C→...]
```

### Step 2: 版式审查（数据填充前）

**目标**：先用空数据/单数据点验证版式，不浪费真实数据渲染轮次。

- 每个信息位是否有对应容器（card/chart/table）
- 大段文字容器是否设了 `max-height` 或 `overflow`
- 左右布局（如 1-B/1-C 并列）不放过多内容
- 模块 6 综合洞察区各段文本长度是否匹配

**输出**：版式审查结论（通过/需调整项）

### Step 3: 模块完整性底线

**目标**：定义每个模块不可删除的内容和可精简的部分。

> 🛑 每个项目必须在项目级技能中列出自己的模块完整性底线表。
> 通用模板如下：

| 模块 | 必须存在 | 可精简 | 可延后 |
|:--|:--|:--|:--|
| {模块名} | {不可删除的最小集} | {可省略的部分} | {以后再做} |

**约束**：
- 出现子模块编号 X-B 时必须存在 X-A
- 🛑 **子模块编号必须严格连续无跳跃**（如 6-D→6-G→6-E 为严重违规）
- 🛑 **新增子模块插入中间位置时，必须全量重新编号后续模块**（不可保留跳跃编号）；包括子标题、HTML 注释、正文交叉引用三处同步更新
- 决策/行动清单结尾必须点名具体实体

### Step 4: 数据入口审计

**目标**：确保所有下游数据都从同一入口流出，禁止独立副本。

- 指定一个脚本/模块为「唯一主数据入口」
- 所有子分析脚本必须调用与主入口同源的数据
- **禁止**直接读取过时路径或独立 CSV

### Step 5: 版本三统一断言

必须满足三个一致：
1. 输出文件名版本号 = 报告内标题版本号 = `<title>` 标签版本号

```python
assert output_filename_version == report_title_version == html_title_version
```

### Step 6: 阶段验收断言

| 阶段 | 断言举例 | 不通过处理 |
|:--|:--|:--|
| 数据层 | 实体总数 = 预期值 | **停止** |
| 数据层 | 单实体最少字段数 ≥ 阈值 | **停止** |
| 数据层 | 所有数据滞后警告已标注 | **停止** |
| 构建层 | canvas 数 = chart 实例数 = 页脚数 | **停止** |
| 构建层 | validate 脚本全绿（0 error, 0 warning） | **停止** |
| 内容层 | 决策清单存在 + 点名具体实体 | **停止** |

> 🛑 每个项目必须列出自己的断言（具体阈值、脚本名、预期值）

### Step 7: 术语/文本一致性扫描

- 术语统一：替换后二次扫描双写错误（如 "SSCRM"）
- 🆕 **外部数据源名称标准化**：新增外部数据（调查/问卷/第三方）的实体名称，**必须统一为报告主体的权威归档名称**。例如调查中的简称（"阿普奇电子"）必须替换为档案标准名（"成都阿普奇电子销售有限公司"），全文统一。如有模糊匹配，必须在报告中注明对应关系。
- 名称完整：实体名截断 ≥20 字符
- 数值精度：`round()` 或 `:.1f`，禁止 `21.20000003%`
- 🆕 **交叉引用版本检查**：子模块重新编号后，必须全文搜索 `详见X-Y` 等交叉引用模式，确认目标编号存在且正确。禁止出现交叉引用指向不存在的编号。

## 禁止行为

| ❌ | ✅ |
|:--|:--|
| 未做预检就写迭代计划 | Step 1 全绿后再写 |
| 字段缺失率高仍硬画空图 | 改用文本说明或替换维度 |
| 决策/行动清单遗漏 | 任何精简版都必须保留 |
| 子模块用独立数据源 | 统一入口 |
| 用户发现一个点修一个点 | 按本技能一次性补齐同类问题 |
| 构建后 validate 有警告仍交付 | 全绿（或用户接受的非阻断项） |
| 🆕 插入子模块后保留跳跃编号（如 6-D→6-G） | 全量重新编号，包括标题+注释+交叉引用 |
| 🆕 报告中混用两种渠道名称体系 | 外部数据实体名统一为报告权威归档名称 |
| 🆕 重新编号后不更新交叉引用 | 全文搜索 `详见X-Y`，逐一验证目标存在
