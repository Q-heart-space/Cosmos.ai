# 技能文件规范（Skill File Spec）v1.0

> **定标**：2026-09-16 | **来源**：好技能 8 条标准 + AI 真实跑经验 + 前后一致性实战教训
> **用途**：skill-review 语义修复的「约定」——SKILL.md/references/frontmatter 怎么写、前后如何一致

## 一、frontmatter 字段约定

| 字段 | 必填 | 约定 |
|:--|:--:|:--|
| `name` | ✅ | 技能名（kebab-case） |
| `description` | ✅ | **一句话定位 + 触发词**；版本号须与 `version` 一致 |
| `version` | ✅ | 语义版本（x.y.z） |
| `depends` | ✅ | **必须 `[]`**（无硬依赖；软依赖走 suggests） |
| `suggests` | ✅ | 软依赖列表（缺失可降级） |
| `triggers` | 条件 | 触发词列表（与 description 触发词一致） |
| `circuit`/`layer`/`space_scope` 等 | 条件 | 按技能类型 |

## 二、SKILL.md 正文结构约定

```
① 核心定位（一句话：做什么）
② 整体框架（## 章节反映「模式/步骤/环节」全貌）
③ 范围映射（触发词→执行范围；有「部分 vs 全部」区分的技能必须写）
④ 执行步骤（步骤名 + 核心要求 + 阻断级标记）
⑤ 核心判据表（分级/路由/四分法 → 放主体，不外置）
⑥ 详细参考指针（🔗 详细见 references/xxx.md——一句话说明）
```

## 三、references 格式约定

```
- 每个文件对应一个「详细主题」
- 文件头部：# 标题 + 一句话说明
- SKILL.md 指针与 references 文件名一致（无死引用）
```

## 四、前后一致性约定（语义修复重点）

| 检查 | 约定 |
|:--|:--|
| description 版本号 = version 字段 | 必须一致（如 description 说 v3.24，version 必须 3.24） |
| description 模式/步骤 = 正文实际 | description 说「12 模板」，正文必须有 12 模板（或索引） |
| description 触发词 = triggers 字段 | 触发词不遗漏、不冲突 |
| SKILL.md 指针 = references 文件 | 指针引用的文件必须真实存在 |
| 步骤清单 = 详细步骤 | 清单的步骤名 = references 里的步骤名 |

## 五、语义修复流程（约定）

```
① 读 SKILL.md 全文（frontmatter + 正文）
② 核对 8 条好技能标准 + 本规范（前后一致性/属性/结构）
③ 识别语义缺口（非 grep 表面，而是「读内容判断」）
④ 语义修复（改内容，非机械替换）
⑤ 真实验证（读回确认 + frontmatter 合法 + 前后一致）
```

## 六、禁止（语义修复红线）

- ❌ 机械替换（只改版本号字符串，不改语义）
- ❌ grep 数量当「完整」（须读实际内容判断）
- ❌ 外置核心判据（分级/路由/四分法必须留主体）
- ❌ 过度压缩（触发入口/范围映射/双向联动不外置）
