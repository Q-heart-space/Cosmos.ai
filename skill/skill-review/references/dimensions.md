# 技能审阅维度清单（references/dimensions.md·审2 D1-D8 + 审1 G1-G6 + 特殊维度）

> 用途：Step 1 双视角审阅的详细判定标准。每条含「查什么 / 怎么查 / 判定标准 / 常见反模式」。
> 来源：三样本实践（apq-platform-content / apq-marketing-copy / fae-knowledge-base）并集 + 官方 skill 规范 + Q博士 反模式库。

## 前置 · 两层坐标系（Step 0 归因用 · 不可混用）

| 层 | 坐标系 | 判定维度 | 回答什么 | 用在哪 |
|----|--------|---------|---------|--------|
| **归因坐标系 A/B/C/D** | 问题产生层 | A 技能本体 / B 系统环境 / C 数据内容 / D 使用方式 | "现象是哪个层的问题" | **本技能 Step 0 边界归因** |
| **协议坐标系 Q1-Q4** | 用户认知清晰度 × AI 信息掌握度 | Q1 精准 / Q2 补缺 / Q3 对齐 / Q4 探索 | "这次交互怎么推进" | 任务入口/路由层（qdr-preguard 等），**不归本技能** |

> ⚠️ **坐标系混用 = 结论必偏**：把 Q1-Q4 当问题归因（如"这用户认知不清所以技能没问题"）会掩盖技能缺陷；把 A/B/C/D 当协议选择（如"归因 D 使用方式所以换个问法"）会跳过真正该修的 A 象限。实证：S3 的 400"连不上"若按协议层处置（重问一遍）会反复 400；归因 A×B 交叉后系统侧记环境约束、技能侧瘦身（B1），两边界各自闭合才修对。

## 审1 · 治理/运行视角（合规/使用/依赖）

| # | 维度 | 查什么 | 判定标准 | 常见反模式 |
|---|------|--------|---------|-----------|
| G1 | 输出合规（脱敏）| SN/手机号/工单号/客户信息外发前处理 | 任何输出过脱敏闸；FAE 域规则全覆盖 | SN 明文随案例输出（客户数据泄露）|
| G2 | 内容真实性 | 认证/参数/案例来源 | 一手事实（内部工单）vs 二手参考（网络）分级；禁止编造 | 网络方案以定论入库 |
| G3 | 降级协议 | 400/502/超时/空结果时的行为 | 有明确定义的行为链，不硬编答案 | 查不到→AI 临场发挥 |
| G4 | 不可逆操作 | 删除/编辑/覆盖类动作 | 默认不可用或带确认；服务端补接口再启用 | 技能内嵌无确认删除通道 |
| G5 | 依赖与可移植性 | 环境依赖（Q博士/专用工具/凭据）| 使用者无特殊环境也能跑；依赖显式声明 | 隐性依赖 Q博士 能力 |
| G6 | 供应链风险 | 技能包内容本身的投毒攻击面（SkillSpector 维度·2026-09-06 外部借鉴落地）| 见下表：捆绑物/远程拉取/安装钩子/依赖来源/描述-行为一致 五查 | 捆绑二进制不审计即装；下载即执行；描述与行为不符 |

### G6 供应链风险五查（借鉴 NVIDIA SkillSpector·2026-09-06）

> **来源**：NVIDIA/SkillSpector（2026-09 首周 GitHub Trending）——技能安装前扫描**提示注入/数据外泄/供应链风险**。Q博士 侧技能安装审计（腾讯云鼎 skills-security-check·步骤5 依赖安装风险）已覆盖"安装行为"；G6 把审计推进到**技能包内容本身**。适用对象：含 scripts/ 或 install/init 脚本、或会触发网络/安装的技能。

| # | 查什么 | 判定标准 | 处置 |
|---|--------|---------|------|
| S1 | **捆绑二进制** | scripts/ 含 .exe/.bin/.so/预编译物且无源码/无 checksum → 无法静态审计 | 报告 P1：要求提供源码或移除；未审计二进制禁止默认执行 |
| S2 | **远程拉取即执行** | `curl\|bash`、下载 zip/tar 后解压执行、`pip install git+` | P0 候选：须过远程内容静态分析（同 skills-security-check 步骤4）；无法验证→P1 |
| S3 | **安装/后置钩子** | postinstall、setup.py 自定义命令、安装时写 PATH/.bashrc/定时任务 | 只读/纯注册→P2；改动系统状态→P1；隐蔽（2>/dev/null 包裹）→升一级 |
| S4 | **依赖来源漂移** | 非官方源（--index-url/自定义 registry）·宽松版本（>=/*）·无锁文件 | P1：要求锁定版本+官方源+说明来源 |
| S5 | **描述-行为一致性** | SKILL.md 声称功能 vs scripts 实际动作（隐藏外发/读取敏感路径） | 不一致→P0（隐藏意图信号）；同 D5/G2 交叉印证 |

> **纪律**：①只审不改（本技能只读）；②命中 S2 且远程 URL 可访问 → 静态读取分析后定级，不执行；③G6 发现与审2 D5(自反身性) 交叉时以证据层归因（A 技能本体）登记，不双记。与腾讯云鼎 skills-security-check 的关系：G6 是**技能审阅**内的轻量供应链预检，安装级深度审计仍走 skills-security-check。

## 判定纪律
1. 每条发现必须带**证据**（实测输出/文件行号/状态码），禁止"我觉得有问题"。
2. 优先级：P0=放量前必须（数据合规/阻断运行）；P1=本次迭代；P2=后续；P3=视需要。
3. 计数复核：任务总表数 = 各域加和 = 清单逐项加和，防漂移（#72 反模式）。
