# 好技能判断标准（Good Skill Criteria）v1.0

> **定标**：2026-09-16 | **来源**：AI 真实执行流程第一原理推导 + 体积瘦身「机械压缩→运行偏差」实战教训
> **用途**：skill-review 审2「运行视角」的判断标准——什么是「好技能」，什么放主体/参考

## 一、第一原理：AI 执行技能的 5 阶段

```
触发（匹配触发词）→ 加载主体（读 SKILL.md 理解"做什么"）
→ 规划范围（按范围映射判断"执行部分 vs 全部"）
→ 逐步执行（按步骤+核心要求+阻断标记执行）
→ 按需查参考（执行到某步时加载 references 详细说明）
```

## 二、放主体 vs 放参考（划分铁律）

| 层级 | 承载 | 内容 | AI 何时需要 |
|:--|:--|:--|:--|
| **主体（SKILL.md）** | AI 一次性必须知道 | 触发词/核心定位/整体框架/范围映射/步骤骨架/核心判据表 | 触发+加载+规划+执行阶段（全程） |
| **参考（references）** | AI 按需加载 | 详细命令/实证判例/数据表/判据展开 | 查参考阶段（执行到某步时） |

**🛑 铁律**：核心判据（分级/路由/四分法/分流规则）是「功能」，必须放主体；只有「详细说明」才是「知识」，可放参考。**外置功能 = 运行偏差**（2026-09-16 实战判例：task-retro 外置「快速入口」致触发失效、task-router 外置「路由表」致路由器失效）。

## 三、好技能 8 条判断标准

| # | 标准 | 判断方法 | 缺失后果 |
|:--|:--|:--|:--|
| 1 | **触发准确** | 触发词完整且无冲突（description + triggers） | 无法正确触发 |
| 2 | **定位清晰** | 一句话说清"做什么"（AI 读后 30 秒理解） | 读后不知所云 |
| 3 | **框架完整** | 整体框架可识别（模式/步骤/环节全貌） | 不知道有几模式/几步 |
| 4 | **范围明确** | 触发词→执行范围映射（部分 vs 全部） | 过度执行或欠执行 |
| 5 | **步骤可执行** | 步骤名 + 核心要求 + 阻断级标记 | 不知道哪些必须做 |
| 6 | **判据在主体** | 核心判据表在 SKILL.md（非仅 references） | 判断时中断查参考 |
| 7 | **参考可查** | references 指针清晰（按需加载不中断） | 详细操作不可得 |
| 8 | **无硬依赖** | depends=[]（suggests 软依赖） | depends 死锁 |

## 四、审阅清单（skill-review Step 1 运行视角用）

```
□ ① 触发词完整且无冲突？
□ ② description 一句话说清"做什么"？
□ ③ 整体框架可识别（## 章节反映模式/步骤/环节）？
□ ④ 触发词→执行范围映射存在（有"部分 vs 全部"区分的技能）？
□ ⑤ 执行步骤有"名+核心要求+阻断标记"？
□ ⑥ 核心判据表在 SKILL.md（分级/路由/四分法/分流）？
□ ⑦ references 指针清晰？
□ ⑧ depends=[] 无硬依赖？
```

## 五、与渐进披露（skill-creator W1-W8）的关系

- skill-creator 的「渐进披露」说「SKILL.md <5k 词，详细外置 references」——**方向对，但缺「核心判据必须留主体」的边界**。
- 本标准补边界：**「核心判据」是「功能」，不是「详细说明」，不能外置**。
- 判例：体积瘦身把「路由表/四分法/触发入口」外置 → AI 无法路由/分诊/触发 → 运行偏差。
