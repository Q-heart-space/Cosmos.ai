# 采用指南：你可能不需要本技能

## 先说这个

如果你的目标是「让 AI 少跑偏」，**本技能不是第一选择**。

下面五件事平台原生就有，而且每一条都比本技能强。**先做完这五件**，再回来看本技能还有没有剩余价值。

| # | 做什么 | 覆盖 | 为什么比本技能强 |
|:--|:--|:--|:--|
| 1 | 要探索时开 **plan mode / 只读模式** | S1、S10 | 从根上**没有写权限**，而不是"请求它别写" |
| 2 | 危险操作交给**沙箱 + 审批策略** | S3、S7 | 内核级强制，不依赖任何钩子 |
| 3 | 项目规矩写进 **`AGENTS.md`** | S1 S2 S6 S7 S8 | 一处生效、所有 runtime 都读；本技能的信号只是它的一个子集 |
| 4 | 产物校验挂 **pre-commit + CI** | S5 | 约束的是**产物**不是模型；除 `--no-verify` 外无法绕过 |
| 5 | 改完让**另一个 agent 独立复核** | S6 | 比"让模型自己检查自己"可靠 |

这五条加起来，覆盖了本技能大约 80% 的意图。

## 什么时候本技能才值得上

三条**同时**满足：

1. 上面五件已经做了，仍然存在**具体的、可复现的**跑偏模式（不是"感觉它有时候会……"）；
2. 那个模式的触发条件是**可判定的**——能写成谓词，而不是"我觉得这样不好"；
3. 你愿意交付**宿主侧的钩子**，而不是只放一份提示词。

三条缺一条，本技能都只会给你一个"看起来装了"的东西。

> 判据的完整推导见 [`first-principles.md`](first-principles.md)。
> 第 2 条尤其重要：它直接决定了某条规则**永远做不到硬拦截**。

## 落地顺序

### 第一步：只做 Tier A

只上**误报率≈0**的规则。宁可只有两条，也不要放进去一条会误伤的。

典型起步：本协议的 `S5`（产物占位符泄漏）和 `S9`（说停就停）。
两者都是精确匹配，几乎不可能误伤。

**先接 CI，再接运行时。** CI 那一层不需要任何 AI 平台，也最难被绕过：

```bash
node references/drift-guard-core.mjs check $(git ls-files '*.html' '*.htm')
```

### 第二步：如果要 Tier B，想清楚摩擦

Tier B 是"在对的时机注入提醒"。它比提示词强（模型不会漏看），但**它每一轮都会往对话里插话**。

在开之前问自己：**这条提醒一年里会触发几次？其中几次是真的？**
如果触发频繁而命中率低，它就是在制造噪音，最后会被关掉——和误报一样。

### 第三步：Tier C 写进 `AGENTS.md`，不要写进这里

Tier C 是价值判断，本来就不该由本协议承载。
把它们写进项目自己的 `AGENTS.md`，让所有工具都能读到，比塞进一个技能里更有效。

## 不要做什么

| 反模式 | 为什么 |
|:--|:--|
| 往 Tier A 里加"判断类"规则 | 误报会杀死这个守卫——**有效保护时间趋近于零** |
| 重复平台已有的能力（沙箱、审批、plan mode） | 多一层不会更安全，只会多一个误报面 |
| 声称 Tier C "被保证了" | 提示词没有强制力。这是本协议最容易犯的自我欺骗 |
| 只交付提示词就宣布"已接入" | 技能是缝1（上下文），结构上不可能是强制。见 [`first-principles.md`](first-principles.md) |

## 一句话

**本技能的价值不在于它装了多少条规则，而在于它告诉你哪些规则值得装成闸门、哪些装了也没用。**

如果你的结论是"我只需要其中两条"，那这个结论是正确的使用方式。
