### 🆕 13. 记忆迭代深度管线（Phase 2A.2·2026-07-04）

> 来源：Q博士综合工作规划 Phase 2A.2 — 记忆从原始日志到专家知识的蒸馏管线。
> 三步升级：每日日志 → 周摘要 → 月规则提案 → 专家知识库。

#### 13.1 三步管线

```
┌──────────────────────────────────────────────────────────┐
│  日日志                                              │
│  .workbuddy/memory/YYYY-MM-DD.md                     │
│  (原始事件·非结构化)                                    │
│       │                                                  │
│       ▼ distill_weekly()                                │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 周摘要 (.workbuddy/memory/weekly/YYYY-WXX.md)      │ │
│  │ 提取：关键事件 → 重复模式 → 待升级规则 → 新增技能    │ │
│  │ 时间窗口：周一~周日                                  │ │
│  └────────────────────────────────────────────────────┘ │
│       │                                                  │
│       ▼ distill_monthly()                               │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 月规则提案 (.workbuddy/memory/monthly/YYYY-MM.md)   │ │
│  │ 提取：可升级铁律 → 技能变更建议 → 技能合并/删除      │ │
│  │ 时间窗口：当月 4 周摘要汇总                          │ │
│  └────────────────────────────────────────────────────┘ │
│       │                                                  │
│       ▼ write_to_expert_kb()                            │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 专家知识库 (drq/patterns/ / rules/ / sops/)         │ │
│  │ 写入：稳定规则 → 可复用模式 → SOP → 检查清单         │ │
│  │ 验收：经 4 周以上验证无回退的规则方可入专家库         │ │
│  └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

#### 13.2 distill_weekly() — 周摘要生成

**输入**：`.workbuddy/memory/YYYY-MM-DD.md`（本周7天的日志文件）

**输出**：`.workbuddy/memory/weekly/YYYY-WXX.md`

**提取规则**：

| 维度 | 提取方法 | 输出格式 |
|:--|:--|:--|
| 关键事件 | 日志中标记为 🔴/🟡 的行 | `**{日期}** — {摘要}（来源: {文件}:{行号}）` |
| 重复模式 | 本周内 ≥ 2 次同类事件 | `⚠️ 模式: {描述} — {发生次数}次 → 建议: {规则/技能}` |
| 待升级规则 | 本周新增/修改的临时规则 | `📋 候选规则: {规则名}（来源: {日期}）→ 需经 {N} 周稳定后升级为铁律` |
| 新增技能 | 本周创建的技能 | `🔧 新技能: {技能名}（{路径}）` |
| 未闭环任务 | >3 天未更新的 in_progress | `⏳ 未闭环: {任务}（{天数}天）` |

**生成时机**：每周日 11:30（与周度复盘联动，复用复盘数据）

#### 13.3 distill_monthly() — 月规则提案

**输入**：`.workbuddy/memory/weekly/YYYY-WXX.md`（当月4份周摘要）

**输出**：`.workbuddy/memory/monthly/YYYY-MM.md`

**升级判断（3选1）**：

| 条件 | 动作 | 目标 |
|:--|:--|:--|
| 周摘要中同一"候选规则"出现 ≥ 3 次 | **升级为铁律** | `<宿主配置根>/MEMORY.md` |
| 周摘要中同一"候选规则"出现 2 次 | **保留候选**，标注"下月再审" | 候选池 |
| 周摘要中"重复模式"导致 ≥ 2 次错误 | **创建技能** | `<宿主配置根>/skills/` |

**验收**：每条升级必须有 ≥ 2 次证据链（不同日期的日志引用）。

#### 13.4 write_to_expert_kb() — 专家知识库写入

**输入**：月规则提案中标记为"可入库"的条目（≥ 4 周稳定验证）

**目标目录**（Q博士 drq 库）：

| 知识类型 | 写入路径 | 格式 |
|:--|:--|:--|
| 可复用模式 | `drq/patterns/{类别}/{名称}.json` | JSON schema（含来源/日期/证据链） |
| 稳定规则 | `drq/rules/{名称}.md` | Markdown（含铁律字母/适用场景/违反后果） |
| SOP | `drq/sops/{名称}.md` | Markdown（含步骤/前置条件/回滚策略） |
| 检查清单 | `drq/checklists/{名称}.md` | Markdown（含逐项检查/自动/手动标注） |

**稳定验证标准**：规则在记忆中 ≥ 4 周无回退、无矛盾、无用户修正 → 方可入库。

**反模式**：
- ❌ 当日新增规则直接入库（未经验证）
- ❌ 月规则提案全部入库（只入库经验证稳定的）
- ❌ 入库后不再回顾（入库 ≠ 终结，季度审计仍需检查）

### 🆕 14. 自动化依赖链规则（Phase 2A.3·2026-07-04）

> 来源：Q博士综合工作规划 Phase 2A.3 — 任务间链式依赖，前一步失败则后续不执行。

#### 14.1 核心规则

```
任务 A 的输出是任务 B 的输入
     └─ 任务 A 失败 → 任务 B 不执行
     └─ 任务 A 成功 → 任务 B 自动触发
```

#### 14.2 已知依赖链

| 链条 | 上游 | 下游 | 失败策略 |
|:--|:--|:--|:--|
| **渠道→报告** | `channel-analysis`（渠道数据刷新） | `apq-data-pipeline` → `report-iteration-steward` | 渠道数据刷新失败 → 不启动报告重建，告警"数据过期" |
| **报告→推送** | `apq-report-deliver`（PDF 构建） | `wecom-push`（企微推送） | PDF 构建失败 → 不推送，告警"构建失败" |
| **四元组** | 周度复盘（产出新铁律） | 记忆巡检（消费 handoff）→ 记忆修复 → 流程日记 | 任一环节失败 → handoff 标记 broken，下个周期重试 |
| **数据中枢** | ERP/CRM 缓存刷新 | `apq-data-pipeline` 清洗 | 缓存刷新失败 → pipeline 使用过期数据 + 标注"数据新鲜度风险" |
| **记忆巡检** | `memory-self-healing`（生成 report.json） | `memory-management --from-report`（消费修复） | report 缺失 → 先跑巡检，再修复 |

#### 14.3 依赖链执行协议

```
1. 定义阶段
   ├─ 每个自动化/技能在 SKILL.md 中标注：
   │   ├─ consumes: [上游任务ID1, 上游任务ID2]   # 消费哪些上游产出
   │   └─ produces: [下游任务ID1, 下游任务ID2]   # 产出被哪些下游消费
   │
2. 执行阶段
   ├─ 执行前：检查 consumes 中所有上游的最后运行状态
   │   └─ 任一上游 FAILED → 阻断，记录 "chain_broken: task_id"
   │   └─ 所有上游 SUCCESS → 继续
   ├─ 执行中：正常执行
   └─ 执行后：更新 state.json 中的 handoff 状态
       └─ SUCCESS → 下游可消费
       └─ FAILED → 下游 blocked

3. 断裂修复
   ├─ chain_broken 持续 > 24h → 告警
   ├─ chain_broken 持续 > 7d → 人工介入
   └─ 上游修复后 → 下游自动恢复（不需要手动重启）
```

#### 14.4 依赖声明模板

在相关 SKILL.md 末尾追加：

```markdown
## 自动化依赖链声明

| 角色 | 任务ID |
|:--|:--|
| **consumes** | upstream-task-1, upstream-task-2 |
| **produces** | downstream-task-1 |
| **failure_policy** | upstream_failure → BLOCK（不执行） |
```
