### 🆕 10. 提示词一致性诊断（2026-07-03 确立）

> **来源**：模板 D（全空间跨时空复盘）在三个空间（产品开发/记忆系统设计/Claw-Automation）输入同一指令词，结果不一致——产品开发全部输出+同步，记忆系统占位符未填充+无输出，Claw-Automation 阶段等待需确认。

#### 10.1 根因框架（6类）

任何跨空间复用的提示词模板，出现不一致输出时，按以下顺序诊断：

| 诊断 # | 检查项 | 方法 | 对应修复 |
|:--|:--|:--|:--|
| 1 | 记忆基线是否一致？ | 对比各空间的 MEMORY.md 内容量和日志密度 | 在模板开头硬编码读取顺序 |
| 2 | 模板是否含占位符？ | grep `【` `X 天` `X 个` | 改为"自动从 MEMORY.md 推断" |
| 3 | 是否含多阶段/分步指令？ | 搜索"阶段1""Step 1""然后""接着" | 改为"一次性完成全部" |
| 4 | 写入指令是否强制？ | 搜索"推送到""建议""可以" | 改为"Write/Edit 到"+"回复列出路径" |
| 5 | 是否含确认等待语？ | 搜索"是否继续""确认""下一步" | 加"禁止确认，直接违规" |
| 6 | 输出格式是否固定？ | 检查是否指定了 Markdown 表格字段 | 改为固定表格（字段写死） |

#### 10.2 诊断流程

```
模板在多个空间表现不一致
    │
    ├─ 诊断1：对比各空间 MEMORY.md 差异 → 记忆基线不一致？
    │   是 → 硬编码读取顺序 + 重写模板
    │   否 → 继续
    │
    ├─ 诊断2-6：逐一检查模板文本 → 存在占位符/分阶段/软写入/确认语/格式不固定？
    │   是 → 按 v2.0 六原则重写（原子操作·零占位符·立即写入·双分类·禁止确认·固定表格）
    │   否 → 模板本身没问题，问题在 AI 执行层
    │
    └─ 修复后验证：在新空间测试，5项标志全部通过 → 修复完成
```

#### 10.3 模板版本化规则

所有复盘/指令模板必须有版本号。模板修改后：
1. 版本号 +1.0
2. 在模板开头记录修订原因
3. 旧版本保留在 `references/` 目录备查

#### 10.4 记忆基线对比工具

检查两个空间的记忆加载差异：
```bash
# 对比空间A和空间B的 MEMORY.md 大小和日志数量
echo "空间A:" && wc -c "空间A/.workbuddy/memory/MEMORY.md" && ls "空间A/.workbuddy/memory/" | wc -l
echo "空间B:" && wc -c "空间B/.workbuddy/memory/MEMORY.md" && ls "空间B/.workbuddy/memory/" | wc -l
# 差异>30% → 记忆基线不一致，需在模板中补偿
```

### 🆕 12. 创新源头保护规则（2026-07-04 提取自复盘指南 v3.2）

> **来源**：跨项目全量复盘指南 v3.2 §六 PTN-15-PTN-18——低活跃空间中可能存在 Q博士智能体的雏形或创新点，传统记忆管理遗漏这些文件。

#### 12.1 低活跃·高价值文件识别

记忆管理中的**修剪/归档操作**，必须跳过以下信号的文件：

| 信号 | 识别方法 | 保护动作 |
|:--|:--|:--|
| 文件名含"框架""评估""模型""评分""设计" | glob + grep | 标记"🔑 创新源头"——跳过修剪 |
| 文件内容同时涵盖 ≥ 2 个不同主题 | AI 分析主题簇 | 标记——不可拆分 |
| 文件在临时空间但被其他空间引用 | grep 全空间引用 | 迁移到目标空间 |
| 用户在本文件中表达了明确的设计意图 | 搜索"目的""目标""要解决的问题" | 标记——不可删除 |

#### 12.2 修剪/归档时的创新保护检查

每次执行记忆修剪（§6）或归档时，必须先检查：
1. 该文件是否匹配上述任一信号？
2. 是 → 标记"🔑 创新源头——跳过修剪"，列出文件路径
3. 否 → 正常修剪

#### 12.3 空间形态五分类法（PTN-15·v3.5）

五类空间形态对应不同的记忆管理策略：

| 形态 | 记忆重点 | 修剪策略 |
|:--|:--|:--|
| 报告密集型 | 版本历史、数据源标注、竞品方法论 | 旧版本归档，方法论保留 |
| 数据管线型 | 管道可靠性记录、口径变更日志 | 数据口径变更不可删 |
| 智能体运营型 | 运维稳定性记录、外部依赖名单、自动化可靠性日志 | 依赖名单不可删，稳定性记录3月归档 |
| 自动化生产线型 | 推送链路校验、信源覆盖记录、格式变更日志 | 校验失效项归档，信源记录保留 |
| 🆕 元治理基础设施型 | 铁律演进、META库、空间类型候选池 | **铁律/META/分类器不修剪** |
| 实验探索型 | 🔑 全部保留——实验空间不修剪 | **不修剪** |

> v3.5 更新：从四分类→五分类（新增元治理基础设施型+自动化生产线型）。空间类型识别规则见 `audits/[复盘]跨项目全量复盘指南.md` §四 Step 2·四（模板G）和 PTN-19。🆕 拆分后：规则仍在主指南 §四，PTN 索引见 `audits/[复盘]模式编号索引_redirect.md`。

#### 12.4 关联升级检查（PTN-18）

memory-management 在收到复盘写入后，必须检查：
1. 是否有新的自动化需求？（如"定期扫描创新源头"）
2. 是否有脚本需要同步更新？（如监控脚本的触发条件）
3. 技能边界是否被复盘发现突破？（如新发现的模式超出当前技能）

#### 12.5 🆕 复盘报告文件保护（2026-07-04）

> **来源**：首次全空间全时间复盘——每个空间生成独立 `复盘报告_YYYY-MM-DD_HHmm.md`，这些文件是跨空间对比和历史追溯的唯一来源。

**保护规则**：
- `复盘报告_*.md` 文件 → **永不修剪、永不归档**
- 这些文件是复盘方法论的演进证据链，即使对应空间已废弃也不删
- 周度自动化复盘生成的报告同样受保护
