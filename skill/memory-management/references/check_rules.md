# 记忆检测规则库

> 共享规则库 —— `memory-self-healing` 和 `memory-management` 共用，避免逻辑分裂。

## 规则分级定义

| 级别 | 含义 | 自动修复 | 人工介入 |
|:--|:--|:--:|:--|
| **P0** | 严重冲突/矛盾，涉及判断 | ❌ 禁止 | 必须 |
| **P1** | 可客观验证的问题，有明确修复方案 | ✅ 备份后自动 | 不需要 |
| **P2** | 纯机械操作，无歧义 | ✅ 直接自动 | 不需要 |

---

## 类别A：铁律/规则冲突检测（P0）

### A-01 铁律字母冲突
- **触发**：`~/.workbuddy/MEMORY.md` 中存在两个相同字母的铁律标题
- **检测命令**：
  ```bash
  grep -oP '铁律[A-Z]' ~/.workbuddy/MEMORY.md | sort | uniq -d
  ```
- **严重度**：P0
- **修复**：保留较新的，重命名旧的（需人工判断保留哪个）
- **自动修复**：否

### A-02 铁律内容重复
- **触发**：两条不同铁律描述同一规则，内容重叠 > 60%
- **检测**：AI 语义比对（需读取全文后判断）
- **严重度**：P0
- **修复**：合并为一条，删除较旧版本
- **自动修复**：否（合并需要判断语义）

### A-03 规则自相矛盾
- **触发**：铁律A说"必须用X"，铁律B说"禁止用X"
- **检测**：AI 语义比对矛盾模式
- **严重度**：P0
- **修复**：标记矛盾，需用户裁决
- **自动修复**：否

---

## 类别B：规则可执行性审计（P1）

### B-01 铁律缺少检查机制
- **触发**：铁律文本中不包含"grep""检查""验证""审计""脚本"等可验证关键词
- **检测命令**：
  ```bash
  grep -A 20 '^## 🛑 铁律' ~/.workbuddy/MEMORY.md | grep -c '检查\|验证\|grep\|审计\|脚本\|确认'
  ```
- **严重度**：P1
- **修复**：在铁律末尾标注 `⚠️ 缺少检查机制，建议补充`
- **自动修复**：否（仅标注，不修改铁律原文）

### B-02 铁律缺少阻断后果
- **触发**：铁律文本中不包含"禁止""停止""阻断""后果""违规"等阻断性关键词
- **检测命令**：
  ```bash
  grep -A 20 '^## 🛑 铁律' ~/.workbuddy/MEMORY.md | grep -c '禁止\|停止\|阻断\|后果\|违规\|不可'
  ```
- **严重度**：P1
- **修复**：在铁律末尾标注 `⚠️ 缺少阻断后果，建议补充`
- **自动修复**：否（仅标注）

### B-03 铁律使用"应该"而非"必须"
- **触发**：铁律原文含"应该""建议""最好"等软性措辞
- **检测命令**：
  ```bash
  grep -A 20 '^## 🛑 铁律' ~/.workbuddy/MEMORY.md | grep '应该\|建议\|最好\|尽量'
  ```
- **严重度**：P2
- **修复**：自动修正为"必须"，并在变更日志记录
- **自动修复**：是（仅改措辞，不改语义）

## 类别C：过时检测（P1/P2）

### C-01 规则来源已解决
- **触发**：铁律的"来源"描述了一个已解决的问题（如"某API已修复""某bug已在v2.3解决"）
- **检测**：AI 读取每条铁律的"来源"字段并判断
- **严重度**：P1
- **修复**：标记为 `🗄️ 待归档（来源已解决）`，不移除原文
- **自动修复**：是（仅标注，不删除）

### C-02 技能引用过时路径
- **触发**：SKILL.md 中引用的文件路径（py/json/md）已不存在
- **检测命令**：
  ```bash
  for f in ~/.workbuddy/skills/*/SKILL.md; do
    grep -oP '[\w/\\-]+\.(py|json|md)' "$f" | while read p; do
      [ -f "$p" ] || echo "MISSING: $f → $p"
    done
  done
  ```
- **严重度**：P2
- **修复**：在报告中列出失效路径
- **自动修复**：否（路径修正需人工确认新位置）

---

## 类别D：完整性检查（P1/P2）

### D-01 当日日志存在性
- **触发**：当日 `YYYY-MM-DD.md` 不存在
- **检测**：检查文件是否存在
- **严重度**：P2
- **修复**：创建空日志文件（含日期标题）
- **自动修复**：是

### D-02 日志闭环缺口
- **触发**：日志中有"开始""启动"记录但无对应"完成""闭环"记录
- **检测**：AI 读取最近 7 天日志，匹配开启/关闭对
- **严重度**：P1
- **修复**：在日志末尾追加 `⚠️ 未闭环任务：[列表]`
- **自动修复**：是（仅标注）

### D-03 项目覆盖完整性
- **触发**：`<工作空间根>\` 下存在子项目，但其 `.workbuddy/memory/MEMORY.md` 不存在或为空
- **检测命令**：
  ```bash
  for d in <工作空间根>/*/; do
    mem_file="${d}.workbuddy/memory/MEMORY.md"
    if [ -d "$d/.workbuddy" ] && [ ! -f "$mem_file" ]; then
      echo "MISSING: $d"
    fi
  done
  ```
- **严重度**：P2
- **修复**：列出缺失项目
- **自动修复**：否

## 类别E：一致性检查（P2）

### E-01 技能触发词与 MEMORY.md 不一致
- **触发**：SKILL.md 中声明的触发词，与用户 MEMORY.md 中对同一技能的描述不一致
- **检测**：AI 对比 `~/.workbuddy/skills/*/SKILL.md` 的触发词段与 MEMORY.md 中的引用
- **严重度**：P2
- **修复**：在报告中列出不一致项
- **自动修复**：否（需人工确认以哪个为准）

### E-02 三层记忆关键信息不同步
- **触发**：同一规则在 Layer1（云记忆索引）、Layer2（用户MEMORY.md）、Layer3（项目MEMORY.md）中描述不同
- **检测**：AI 读取三层后对比关键词
- **严重度**：P1
- **修复**：报告差异，建议同步方向
- **自动修复**：否

### E-03 CHANGELOG 最后更新超过 7 天但有记忆文件变更
- **触发**：`~/.workbuddy/.MEMORY_CHANGELOG.md` 最后一条记录日期 > 7 天前，但 memory 文件的 mtime 在 7 天内
- **检测命令**：
  ```bash
  # 获取 CHANGELOG 最后日期
  tail -20 ~/.workbuddy/.MEMORY_CHANGELOG.md | grep -oP '\d{4}-\d{2}-\d{2}' | head -1
  # 获取 memory 文件最新 mtime
  stat -c %Y ~/.workbuddy/MEMORY.md
  ```
- **严重度**：P2
- **修复**：在 CHANGELOG 追加 `⚠️ 检测到未记录的变更`
- **自动修复**：是

## 类别F：记忆索引层检查（P1/P2）🆕 v1.1

### F-01 memory_index.json 缺失或过期
- **触发**：项目 `.workbuddy/memory_index.json` 不存在，或生成时间超过 48 小时
- **检测命令**：
  ```bash
  python scripts/capability_freshness_check.py --json | jq '.memory_index'
  ```
- **严重度**：P1（缺失）/ P2（过期但未超 7 天）
- **修复**：调用 `python scripts/update_memory_index.py` 重建索引
- **自动修复**：是（memory-management 可执行重建）

### F-02 L0-L4 五层记忆接口描述不同步
- **触发**：`constitution/本质定位.md` §2.1、项目 `.workbuddy/memory/MEMORY.md` §2.1、`governance/记忆系统接口契约.md` 对 L0-L4 的描述不一致
- **检测**：AI 读取三层文件后对比关键词（L0 平台输入 / L1 全局铁律 / L2 项目宪法 / L3 事件索引 / L4 健康监控）
- **严重度**：P1
- **修复**：报告差异，建议以宪法 `本质定位.md` 为真相源同步
- **自动修复**：否
