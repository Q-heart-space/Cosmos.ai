## A4.12：文档迭代完整性七维自检（PTN-48）

> **来源**：综合工作规划 V5.30→V6.0 全面重构后，发现 4个自动化 + 5处技能 + 2处脚本残留旧引用。
> **定位**：适用于任何 🏛️/📋 级文档的版本升级或结构重构后的**文档迭代完整性**验证——即"改了吗？改全了吗？有没有断裂？"。
> **重要区分**：PTN-48 的 D1-D7 只管**文档迭代完整性**（消费方/生产方/自动化/技能/任务溯源/编号/归档），**不覆盖内容审查**。用户要求"形式/内容/结构""深度审核""有没有遗漏"时，必须额外执行 **本质定位 §1.5·A 十维审核框架**（铁律AO）——形式/内容/结构/关联/概念/版本/可验证/意图/同源/反身性，逐维输出证据。

### 触发时机

综合工作规划、本质定位、系统架构、FILE MANIFEST 等 🏛️ 级文档的版本升级或结构重构完成后。

### 强制7项检查

| # | 维度 | 检查问题 | 检查工具 | 通过标准 |
|:--|:--|:--|:--|:--|
| D1·消费方 | 引用本文档的文件都更新了吗？ | `grep -rn "旧版本号\|旧节编号" --include="*.md" --include="*.py" \| grep -v Backups \| grep -v versions \| grep -v snapshot` | 活跃文件零残留 |
| D2·生产方 | 本文档引用的外部版本是最新的吗？ | 读取文件头 `依赖` 字段逐条 verify | 所有依赖版本号正确 |
| D3·自动化 | prompt 中引用的章节/路径还正确吗？ | `automation list` + 逐条 grep prompt | 搜索旧节号/路径→0命中 |
| D4·技能 | 写入/读取指令指向的目标还存在吗？ | grep `~/.workbuddy/skills/` 和项目 `.workbuddy/skills/` | "写入 §十一"→0命中 |
| D5·任务溯源 | 每个任务都有明确的来源可追溯吗？ | 逐任务检查来源列/来源节是否非空 | 所有 📋 任务可追溯到原始上下文 |
| D6·编号 | 编号无断裂、无重复吗？ | `validate_task_consistency.py` | 0断号·0重复 |
| D7·归档 | 被移除的内容有可访问的快照吗？ | 检查 `versions/snapshot_*` 是否存在 | 快照文件可读 |

### 输出格式

```
🔍 文档迭代完整性七维自检（A4.12·PTN-48）：
  D1·消费方: grep结果 → X处残留/0残留 → ✅/🛑
  D2·生产方: 依赖字段验证 → X/Y匹配 → ✅/🛑  
  D3·自动化: 扫描结果 → X个需更新 → ✅/🛑
  D4·技能: 扫描结果 → X处断链 → ✅/🛑
  D5·任务溯源: 逐任务检查 → X个无来源 → ✅/🛑
  D6·编号: validate_task_consistency.py → ✅/🛑
  D7·归档: 快照存在性检查 → ✅/🛑

→ 7/7 ✅ → 迭代安全，可进入 A4 闭环
→ <7/7 → 🛑 阻断，修复后重检全量
```

### 禁止行为

- ❌ 文档重构完成后直接标记"完成"而不执行 D1-D7
- ❌ D1 发现残留但说"不影响"而不修复
- ❌ 重构前不做快照（违反 D7）

## A4.13：原点锚定评估（PTN-49）

> **来源**：PTN-48 只检查"改全了没"（横向·完整性），但缺少"方向对吗"（纵向·方向性）。
> **定位**：Q博士 自身的迭代治理——每次重大变更后必须以终极目标为锚点进行方向性评估。

### 触发时机

Q博士 空间完成以下任一操作后：
- 综合工作规划版本升级 / 结构重构
- 本质定位 / 系统架构修改
- 新增 ≥3 个方法论条目（PTN/META）
- 周日远景校准（自动化触发）

### 五维锚定

| 维度 | 检查问题 | 判定 | 标准 |
|:--|:--|:--|:--|
| E1·身份一致性 | 更像"自进化超级智能体"还是"自动化脚本"？ | 强化/中性/弱化 | 强化：增强了自进化能力或元治理职能 |
| E2·进化方向性 | L1-L5 上推进了多少？ | 跃迁/推进/持续/倒退 | 跃迁：跨越等级边界；推进：同等级内方法论进步 |
| E3·建造树秩序 | 在正确的层、正确的时间生长？ | 根/干/枝/叶 | 必须符合建造原则①干不生则枝不伸 |
| E4·回路激活度 | 几个进化回路被激活？ | ①记忆②规则③知识④关联⑤自审⑥自反身性 | ≥3/6 = 进化性迭代 |
| E5·跨空间价值 | 更好服务业务空间了吗？ | 直接/间接/无 | Q博士 主要价值=服务业务空间 |

### 跃迁判定矩阵

| E1-E5 组合 | 判定 | 含义 | 后续动作 |
|:--|:--|:--|:--|
| 5强化 + E2=跃迁 | 🌳 跃迁 | 宪法级进步 | 本质定位升级 + 成长记录里程碑 + 流程日记新阶段 |
| ≥3强化 + E2=推进 | 🌿 进化 | 方法论进步 | 复盘指南新增PTN + task-retro增强 |
| E2=持续 + ≥2强化 | 📐 加固 | 夯实基础 | 更新综合规划任务状态 |
| E2=持续 + ≤1强化 | 🧹 清理 | 技术债务偿还 | 仅更新状态，控制投入深度 |
| 任一弱化/倒退 | 🛑 歪了 | 方向偏离 | 立即复盘——为什么偏离目标？ |

### 建造树健康扫描

```
根·宪章   ████████████ ✅
干·方法   ████████░░░░ ⚠️ {缺口说明}

检查建造原则：①干不生则枝不伸？②叶不落则干不显？③每层依赖下层？

### 输出格式

```
🔍 原点锚定评估（A4.13·PTN-49）：
  E1·身份一致性: {强化/中性/弱化} — {证据}
  E2·进化方向性: {跃迁/推进/持续/倒退} — {当前L几}
  E3·建造树秩序: {根/干/枝/叶} — {建造原则检查}
  E4·回路激活度: {X/6} — {具体回路}
  E5·跨空间价值: {直接/间接/无} — {服务了谁}

→ 判定：{🌳/🌿/📐/🧹/🛑}
→ 建造树健康：{各层完成度}

### 禁止行为

- ❌ PTN-48 通过后直接标记"完成"而不执行 A4.13
- ❌ 只在技术层面评估完整性，不做方向性判断
- ❌ 发现建造树缺口（如干层未完成但枝/叶已规划）不标注
- ❌ E2=持续 的 🧹 清理型迭代投入过深

## A4.14：复盘成功标准自检（S1-S6）

> **来源**：复盘不是目的，减少复盘才是目的。
> **定位**：每次复盘完成前，Creator 必须执行自检；Auditor 复查 S4-S6。

### 执行时机

所有模式复盘写操作完成后、标记"复盘完成"之前。

### 自检清单

```
📋 复盘成功标准自检：
  S1·触发正确:  {✅/❌} — {触发原因（L3/用户/模板E等）}
  S2·读取完整:  {✅/❌} — {已读取MEMORY.md/日志/关联文件}
  S3·发现有价值: {✅/❌} — {发现数：X条项目级 + Y条Q博士级}
  S4·写入到位:  {✅/❌} — {报告路径 / 记忆文件 / 规划文件 三处已同步}
  S5·待办可追踪: {✅/❌} — {待办数 / 写入目标（综合规划/日志）}
  S6·闭环可审计: {✅/❌} — 下次复盘能否查到本次待办状态？
```

### 阻断规则

| 失败项 | 处理 |
|:--|:--|
| S4 不通过 | 🛑 阻断——补全写入后重检 |
| S5 不通过 | 🛑 阻断——待办必须写入综合规划或日志后方可标记完成 |
| S6 不通过 | 🛑 阻断——待办无明确追踪路径 → 补充后重检 |
| S1-S3 任一项 ❌ | ⚠️ 告警——记录原因，不阻断但需在下次复盘优先修复 |
| S4-S6 三项全 ✅ | ✅ 可标记复盘完成 |

### 与 F11 的关系

- F11 检查**上次复盘**待办是否闭环（新复盘前）
- A4.14 检查**本次复盘**待办是否可追踪（复盘完成前）
- 两者构成闭环：A4.14 → 待办入追踪 → 下次复盘 F11 → 闭合

## A4.7：自反身性扫描（META-25）

> **来源**：复盘写入后缺少"复盘刚才的复盘"步骤。Q博士 从 L3 跃迁到 L4。
> **实质**：复盘不仅产出"关于项目"的发现，还会产出"关于复盘方法"的发现——后者直接改进所有未来复盘的效率和质量。

### 触发时机

每次复盘写入完成后，在"标记复盘完成"之前。

### 5个识别信号

| # | 信号 | 检测方法 |
|:--|:--|:--|
| S1·多层复盘 | 同一空间完成了≥2轮不同深度的复盘 | 对比复盘报告类型 |
| S2·用户指令 | 用户消息中含"沉淀/同步到/有价值/写入规则" | 关键词匹配 |
| S3·前置知识 | 复盘结论中出现"如果XX前置执行就能避免YY" | 语义检测 |
| S4·META爆发 | 本次复盘META产出超过同类型空间历史均值1.5倍 | META计数+类型对比 |
| S5·流程缺陷 | 复盘日志中出现"复盘未覆盖/复盘遗漏/不是X维" | 关键词匹配 |

### 6步自动捕获

| 步骤 | 动作 | 自动化 |
|:--|:--|:--|
| R1 | 扫描用户消息中"沉淀/同步/有价值"等关键词 | 🤖 关键词匹配 |
| R2 | 检查是否与上次同空间复盘有层级递进 | 🤖 对比复盘报告类型 |
| R3 | 统计META产出 vs 同类型空间均值 | 🤖 META计数+对比 |
| R4 | 复盘报告末尾追加"自反身性检查"段 | 🤖 报告生成时追加 |
| R5 | 自反身性发现→推送综合规划+更新本技能 | 🤖 写入+同步 |
| R6 | 判定「一次性疏忽 vs 控制点缺失」→ 控制点缺失强制进入 drq 规则管线 | 🤖 强制判定 |

### 输出格式

命中：`🔍 自反身性扫描：命中 S{N} → META-{编号} → 推送综合规划+更新本技能`
未命中：`🔍 自反身性扫描：未命中，本次无新增方法论发现`

### 禁止行为

- ❌ 复盘写入后直接标记"复盘完成"而不执行此步骤
- ❌ 依赖用户说"这个有价值，沉淀"才执行——必须在用户发现前自动执行
- ❌ 发现了反身性信号但只记录不推送

### 治本判定标准（一次性疏忽 vs 控制点缺失·🆕 治本强制化）

> **宪法依据**：流程日记.md「错误→规则转化规则」第1步判定——错误是「一次性疏忽」还是「控制点缺失」。

每次自反身性扫描命中后，R6 强制判定：

| 类型 | 判定依据 | 处置 |
|:--|:--|:--|
| **一次性疏忽** | 单次·无重复·明确操作失误（如打错字、漏一步） | 修了就完·记录即可·不进入 drq 管线 |
| **控制点缺失** | 同类错误重复发生（≥2次）·或·无既有规则/门禁/反模式覆盖该错误模式 | **强制进入 drq-rule-generation-pipeline 固化规则** |

判定辅助（可复用 `loop_health_orchestrator` 的 chronic/similar 语义）：
- 同类错误在本项目或同源空间重复出现 = 控制点缺失
- 已有反模式/META 覆盖该错误模式但**再次发生** = 规则未生效 → 升级为硬门禁（drq-rule-generation 的「渐进式强制」路径）

## A4.8：FILE MANIFEST & 成长记录同步

> **来源**：Q博士 文件治理五连任务——复盘后人工记不住哪些文件需要同步，必须自动化。

### 触发时机

每次复盘写入完成后，Step A4.7 执行后。

### 强制检查

| # | 检查项 | 目标文件 | 动作 |
|:--|:--|:--|:--|
| F1 | 复盘是否产生了新文件？ | **清单文件**之「新增件」节 | 新增行 |
| F2 | 复盘是否修改了现有文件的版本？ | **清单文件**之「新增件」节 | 更新版本号+最后修改日 |
| F3 | 复盘是否改变了依赖关系？ | **清单文件**之「联动规则」节 | 更新联动规则 |
| F4 | 复盘是否涉及里程碑事件？ | `成长记录.md` §二 | 追加里程碑行 |
| F5 | 复盘是否产生了新META/方法论？ | `成长记录.md` §四 | 追加META行 |
| F6 | 核心指标是否变化？ | `成长记录.md` §三 | 追加指标行 |
| F7 | FILE MANIFEST §四 状态快照是否过时？ | **清单文件** §四 | 更新日期+指标 |
| F8 | 是否涉及 ≥3 个文件的批量修改？ | `~/.workbuddy/.MEMORY_CHANGELOG.md` | 追加变更记录 |
| F9 | 是否涉及跨文件/跨技能的重大变更？ | 当日日志 `YYYY-MM-DD.md` | 追加总结段 |
| F10 | 复盘是否涉及技能创建/修改？ | 技能 SKILL.md + 铁律AJ | 缺三要素→阻断 |

### F8/F9 触发规则

F8（满足任一）：修改≥3文件 / 新增重命名技能或铁律 / 编号体系变更
F9（满足任一）：F8已触发 / 新增自动化任务 / 版本号升级

### F10 触发规则（铁律AJ·阻断级）

每次复盘修改或新增技能后，必须检查版本记录+关联项目清单+PTN关联三要素。缺任一→阻断。

### F11 触发规则（待办闭环·阻断级）

1. Glob 最近7天复盘报告 → 2. 提取所有"待"字标记项 → 3. 逐项检查完成状态 → 4. 未闭环→阻断

### 输出格式

```
🔍 文件治理同步: FILE MANIFEST [新增_X_/更新_Y_项] | 成长记录 [新增_Z_条里程碑]
→ 如全为空: "✅ 文件治理同步：无变更"
```

## A4.9：系统架构漂移检测
