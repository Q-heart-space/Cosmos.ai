### 🆕 Step A4.10：修复后交叉验证（PTN-42·2026-07-05复盘确立·阻断级）

> ⚠️ **来源（2026-07-05·动态资产V2.0复盘）**：修复了10个问题，仍遗漏综合规划版本表、自动化prompt等3项。根因是修复后没有做交叉验证——"修好了"不等于"修全了"。**只出分析报告 = 白复盘。修复后不验证 = 同样白复盘。**

#### 触发时机

#### 强制5项交叉验证

| # | 验证项 | 方法 | 通过标准 |
|:--|:--|:--|:--|
| **V1·残留检查** | 搜索旧版本号/旧路径/旧函数名是否仍存在于活跃文件中 | `grep -rn "旧标识" --include="*.md" --include="*.py" \| grep -v Backups \| grep -v versions` | 活跃文件零残留 |
| **V2·消费方扫描** | 本次修改的所有文件是否被所有消费方引用最新版本 | PTN-35 动态检索矩阵 | 无断裂引用 |
| **V3·版本一致性** | 文件头版本 vs FILE MANIFEST vs 成长记录版本是否一致 | `asset_health_check.py` VERSION_MISMATCH | 0项 |
| **V4·运行时验证** | 新增/修改的脚本是否能正常运行 | `python script.py --check` 或等效 | 无异常输出 |
| **V5·自查表** | 对照原始任务清单，逐项确认无遗漏 | 列出任务清单 → 逐项打勾 | 全部✅ |
| 🆕 **V6·跨文件引用一致性** | 文件拆分/章节重构后，全项目消费方引用是否正确更新 | `grep -rn "旧章节号\|旧文件路径" --include="*.md"` + `asset_health_check.py` CROSS_FILE_REF | 活跃文件零陈旧引用 |

#### 输出格式

```
🔍 修复后交叉验证（A4.10）：
  V1·残留检查: ✅ 活跃文件零残留（Backups/versions 中N处历史引用不修改）
  V2·消费方扫描: ✅ PTN-35 扫描 X 个消费方，全同步
  V3·版本一致性: ✅ asset_health_check.py VERSION_MISMATCH=0
  V4·运行时验证: ✅ / ⚠️ {异常说明}
  V5·自查表:       ✅ X/X 项全部完成
  V6·跨文件引用:    ✅ CROSS_FILE_REF=0 陈旧引用
→ 全部通过: ✅ 可进入 A4 闭环
```

### 🆕 Step A4.16：跨轮次增量对比（PTN-55·v3.25新增·阻断级）

> **来源**：技能生态元模式复盘——复盘报告是一次性快照，写完归档后下一轮不复用。需要跨轮次增量跟踪。

#### 触发条件
本空间存在 ≥1 份历史复盘报告（Glob `.workbuddy/memory/复盘报告_*.md`）。

#### 强制步骤

```
1. Glob 本空间历史复盘报告 → 加载最新一份
2. 对比:
   ├─ 待办闭合率: 上轮报告的待办项，本轮修复了多少？
   ├─ 重复问题: 上轮报告的问题是否在本轮再次出现？
   └─ 模式演化: 上轮的根因分析是否在本轮被验证/推翻？
3. 判定:
   ├─ 闭合率 < 80% → 🔴 P1 阻断: "上轮 X 项待办仅修复 Y 项，先闭合再新增"
   ├─ 重复问题 ≥2 → 🟡 P2: "问题'Z'在连续两轮复盘中出现，建议升级为铁律或脚本检测"
   └─ 闭合率 ≥ 80% 且无重复 → ✅ 通过
```

#### 输出格式

```
🔍 跨轮次增量对比（A4.16）：
  上轮复盘: 复盘报告_X.md（日期）
  待办闭合率: X/Y = Z%
  重复问题: N 项（Z1, Z2）
→ 通过 / 🛑 阻断
```

#### 禁止行为
- ❌ 非首次复盘但跳过历史报告加载
- ❌ 待办闭合率 < 80% 仍新增同类待办
