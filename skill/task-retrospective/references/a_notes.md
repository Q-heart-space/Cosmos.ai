# 注意事项

## 注意事项

- 不做推断：结论必须有数据或项目日志支撑
- 区分"已修复"和"仍需执行"——审计后标注清楚
- 新增规则前必须扫描 MEMORY.md 现有标签，避免命名冲突
- 单日积分超过 800 必须指出 Token 预算告警缺失
- 模型切换未 `/clear` 导致 Network Error 的调用必须单独标记为"纯浪费"
- 模型效果对比必须基于实际数据（失败率、轮次、成本），不靠主观感受
- 🆕 复盘报告中的"已修复"必须有文件路径和修改内容佐证，不能只说"已修复"
- 🆕 案例库中标注"⏳ 待验证"的条目，下次复盘时必须检查是否复发

### 🆕 复盘报告发布前强制自审（Phase Z·2026-07-03 新增）

> ⚠️ **来源**：IPC v5.3 复盘——用户需要两份报告才闭环（深度复盘 + 补充复盘），说明单次复盘未满足"自验证清单"要求。

**强制步骤**：task-retrospective 在输出复盘报告后、标记任务完成前，必须执行以下自审：

| # | 自审项 | 通过标准 | 不通过处理 |
|:--|:--|:--|:--|
| 1 | 模式覆盖检查 | 复盘覆盖了所有可识别模式（≥ 任务复杂度对应的模式数） | 补充遗漏模式 |
| 2 | 建议可执行性检查 | 每条建议有文件路径/接口/验收标准/责任人 | 补全不可执行建议 |
| 3 | 成本量化检查 | 每个返工项有轮次/积分/可避免比例 | 补全未量化项 |
| 4 | 遗漏检查 | 对照原始任务范围，检查是否有遗漏根因 | 补充遗漏根因 |
| 5 | 关联扫描检查 | 修改的技能/规则是否扫描了所有关联项 | 执行关联扫描 |

**禁止行为**：
- ❌ 复盘报告输出后直接标记"复盘完成"
- ❌ 自审发现遗漏后另起补充报告（应直接在原报告中补充）
- ❌ 只说"建议增强"而不给出具体可执行动作

### 🆕 Step A3.6：复盘深度自动爬升检查（META-26·2026-07-04）

> ⚠️ **来源**：海事工控机研究报告3轮复盘——全时空→超深度→强制深度，S1-S5全命中。证明多轮复盘应自动触发抽象层级爬升，但当前依赖用户手动触发。
> **META编号**：META-26（复盘深度自动爬升机制）

#### 触发条件

每次复盘完成后，在执行 Phase Z 自审之前，自动检查以下5个信号：

| 信号 | 检查方法 | 命中标准 |
|:--|:--|:--|
| **S1·多层复盘** | `Glob` 本空间 `.workbuddy/memory/复盘报告_*.md` | ≥2个 |
| **S2·用户指令** | 正则匹配用户消息 `第一个\|首次\|高密度\|深度复盘\|提炼到Q博士\|沉淀\|同步\|有价值\|写入规则` | 任一命中 |
| **S3·前置知识** | 正则匹配复盘结论 `如果.*前置.*就能避免\|如果.*先.*就不会` | 任一命中 |
| **S4·META爆发** | 本次复盘产出 META 数量 vs 同类型空间均值 | >均值1.5倍（报告密集型≥4个） |
| **S5·流程缺陷** | 复盘报告中含"模板/复盘本身/复盘体系/复盘流程"的批评性描述 | 任一命中 |

#### 执行逻辑

```
1. 判定当前复盘层级：
   L0 = 无历史复盘
   L1 = 历史复盘仅到"具体错误→校验项"层级
   L2 = 历史复盘已到"重复模式→普通模式"层级
   L3 = 历史复盘已到"元模式"层级

2. 检查 S1-S5 → 任一命中？
   ├─ 是 → 判断是否需要升级层级
   │       当前L1且命中→自动升级到L2
   │       当前L2且命中→自动升级到L3
   │       当前L3且命中→生成下一META（自验证循环）
   ├─ 否 → 记录"无升级信号"到复盘报告末尾

3. 自动升级时：
   - 不等待用户确认
   - 在复盘报告末尾追加《🆕 复盘深度爬升判断》段落
   - 如触发新META生成→追加到 综合工作规划 §附录 [方法论]
```
