# 对抗式审查 ＋ 递归闭环修复

> **它解决什么**：多 Agent 跑完之后，**产出看起来是完整的** —— 🅑 而这正是最危险的时候。
> **它的立场**：🎯 **审计的第一步不是"查什么"·🅑 是判"这个结论**凭什么成立**"**。

---

## 一、🎯 四问（🅑 每次审之前先答）

| 🎯 问 | 🅑 不合格之形 |
|:--|:--|
| ① **这个结论的**依据**是什么？** | 🅑 「我读了代码」⇒ 🎯 须给**文件 ＋ 行 ＋ 原文** |
| ② **它**可被证伪**吗？** | 🅑 「应该没问题」⇒ 🎯 须给**能推翻它的观测** |
| ③ **没做的部分**说了吗？** | 🅑 只报"做了什么"⇒ 🎯 须报**没做什么 ＋ 为何** |
| ④ **判据的**覆盖域**够吗？** | 🅑 「门报绿」⇒ 🎯 须问**它扫了什么·🅑 没扫什么** |

---

## 二、🎯 审计维度（🅑 逐维核·🅑 非只核一遍）

| 🎯 维 | 🎯 问什么 |
|:--|:--|
| **形式** | 🅑 结构对否（🅑 产出物之类型与位置） |
| **内容** | 🅑 说的与做的**是**一回事吗？ |
| **结构** | 🅑 各部分**接得上**吗？ |
| **关联** | 🅑 改了 A·🅑 **B 跟着改了吗**？ |
| **概念** | 🅑 同一个词·🅑 **两处一个意思吗**？ |
| **版本** | 🅑 读数**标了口径与时点**吗？ |
| **可验证** | 🅑 换个日子**还能复算**吗？ |
| **意图** | 🅑 做的是**要做的**吗？ |
| **同源** | 🅑 这问题的**同族**在别处有没有？ |
| **反身性** | 🅑 **审计本身**受审了吗？ |

---

## 三、🎯 递归闭环四要件（🅑 缺一即未闭环）

| 🎯 要件 | 🎯 判 |
|:--|:--|
| **同源域** | 🅑 这问题**属于哪一族**？（🅑 族＝同一根因之多处表现） |
| **双向对拍** | 🅑 **两边都量**（🅑 报的 ↔ 实的 ／ 改前 ↔ 改后） |
| **经验→能力** | 🅑 修完**有没有落成一条能跑的判据**？ |
| **可复算** | 🅑 换个日子·🅑 **同命令重跑得同量级**吗？ |

---

## 四、🛑 四条禁令

> **从内存／语义推断文件存在** —— 🅑 **先查磁盘**。
> **把"没报错"当"做对了"** —— 🅑 门报绿**不等于**扫到了。
> **只改读数不改内容** —— 🅑 那是**把红变绿**·🅑 不是修好。
> **断言而不给可复算路径** —— 🅑 **没给命令的结论·🅑 一律按未验证处理**。

---

## 五、🎯 交付时须附（🅑 读者据此复核你）

1. 🅑 **你查了什么**（🅑 命令 ＋ 输出）；
2. 🅑 **你没查什么**（🅑 具名）；
3. 🅑 **判据的覆盖域**（🅑 扫了多少 · 🅑 全量多少）；
4. 🅑 **净变化**（🅑 修了 N ／ 新增 M）。
