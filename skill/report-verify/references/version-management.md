# 版本号管理规范

## 全局同步 8 处

| # | 位置 | 说明 |
|---|------|------|
| 1 | MD 文件封面 `<组织码>-M-AR-YYYY-V{n}` | 手动更新 |
| 2 | MD 文件封面 `v{n} {描述}` | 手动更新 |
| 3 | MD 版本修订记录最新条目 | 手动更新 |
| 4 | 构建脚本 `MD_FILE` 默认路径 | 手动更新（或动态解析） |
| 5 | 构建脚本封面文件编号 `<span>` | 手动更新 |
| 6 | 构建脚本封面版本号 `<span>` | 手动更新 |
| 7 | 构建脚本 `header_template` 页眉 | 手动更新 |
| 8 | 构建脚本打印语句版本号 | 手动更新 |

> **推荐**：构建脚本中实现从 MD 文件动态解析版本号，减少手动同步点。

## 脱敏版命名规范

- 格式：`v{n}.{m}_脱敏版_YYYYMMDD`
- 示例：`v17.3_脱敏版_20260606`
- **禁止**：使用独立版本号导致版本号混淆

## 版本号策略（x.y 格式）

| 场景 | 版本号规则 | 示例 |
|------|-----------|------|
| 日常内容修改 | 保持 `v{n}.{m}`，不升版本 | v17.4 → 仍为 v17.4 |
| 重大结构变更 | 升大版本 `v{n+1}.0` | v17.4 → v18.0 |
| 发版时 | 由 `@skill:report-deliver` 统一升级（🆕 原 `apq-report-release` 已不存在·陈旧指针） | 自动判断 |

> **核心原则**：日常修改阶段不升版本号、不生成 PDF；只有正式发版时才升版本号并生成 PDF。

## 人工审核清单（输出前必查）

| # | 检查项 |
|---|--------|
| A1 | 文件名版本号与封面文件编号一致 |
| A2 | 封面日期为当天日期 |
| A3 | 版本修订记录最新条目准确 |
| A4 | PDF 目视翻页无异常 |
| A5 | 目录链接均可正确跳转 |
| A6 | 脱敏版已同步（如适用）|
| A7 | 竞品官网链接可访问 |
| A8 | 无旧版本号残留 |
