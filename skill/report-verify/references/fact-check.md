# 事实核查工作流

## 触发条件

报告涉及以下数据时，**必须**执行事实核查：
- 客户公司信息（成立时间、注册资本、法定代表人、营收）
- 产品质量数据（简道云记录数、问题类型分布）
- 竞品技术参数（认证状态、接口数量、温度范围）
- 行业市场规模、CAGR、政策文件引用
- 船舶分类与适配方案
- **Hatteland 及竞品产品数据**

## 核查层级

### Tier 1：内部数据源（最高可信度）

| 数据类型 | 来源 | 核查方式 |
|----------|------|----------|
| 质量问题记录 | 简道云 API | 直接统计 JSON，核对记录数与客户覆盖 |
| 跟进记录 | 卫瓴 API | 直接统计 JSON，核对企业数与跟进条数 |
| 出货配置 | 海兰信采购订单配置单 | 与 MD 中表格逐行核对 |

### Tier 2：公开互联网检索（需交叉验证）

| 数据类型 | 最低验证标准 |
|----------|--------------|
| 客户公司基本信息 | 天眼查/企查查 ≥2 个来源交叉确认 |
| 竞品产品参数 | 官网产品页 + 产品手册 PDF + 认证证书扫描件 |
| 船级社认证 | 各船级社官网认证数据库查询 + 厂商产品页标注对比 |
| 竞品官网链接 | 逐条验证可访问性，记录失效链接 |

### Tier 3：推算/估算数据（必须标注）

- 单船价值估算、年需求量推算、营收预测
- 必须标注「[估算]」「按…假设推算」
- 不可作为确定事实陈述

## 禁止行为

- ❌ 未经核实即写入具体数字
- ❌ 将第三方报告中的数据当作事实直接引用
- ❌ 混用不同年份的数据
- ❌ 虚构客户案例或竞品参数
- ❌ 将竞品官网自述的认证状态无条件接受（需区分"声明"与"第三方授予"）

## 核查清单（每次版本升级前必查）

- [ ] 客户数量表述一致
- [ ] 简道云引用注明覆盖客户数和记录数
- [ ] 卫瓴引用注明企业数和跟进条数
- [ ] 所有百分比数据有来源标注
- [ ] 所有推算数据标注「[估算]」
- [ ] 版本修订记录与 MD 正文版本号一致
- [ ] Hatteland 产品参数与官网一致
- [ ] 竞品认证列表已交叉验证
- [ ] 竞品参考链接可访问
- [ ] 船级社认证区分"已获"与"声明"

## 上角标引用规范（对应校验第 24 项）

### 核心规则

关键引用数据（客户需求反馈、竞品参数来源、行业数据出处、政策文件引用）一律使用 `[^N]` 格式。

### 格式标准

| 元素 | 格式 | 示例 |
|:--|:--|:--|
| 正文标注 | `[^N]`，N 从 1 递增 | `海兰信已明确提出显卡需求 [^1]` |
| 来源定义行 | `[^N]: 描述 或 URL` | `[^1]: 海兰信客户需求反馈（2026年6月）` |

### 适用范围

| 必标注 | 可不标注 |
|:--|:--|
| ✅ 客户需求反馈 | ❌ 报告内部交叉引用（用 §X.Y） |
| ✅ 竞品产品参数来源 | ❌ **本组织**自身产品规格 |
| ✅ 行业市场规模/CAGR 数据 | ❌ 公共常识性信息 |
| ✅ 政策文件/法规引用 | ❌ 简道云内部数据 |
| ✅ IMO/CCS/IEC 标准文件 | |
| ✅ 第三方研究报告数据 | |
| ✅ 竞品定性结论 | |
| ✅ 趋势预测/展望数据 | |
| ✅ 图表来源 | |

### 常见遗漏场景

| 典型表述 | 风险 | 正确标注 |
|:--|:--|:--|
| "达文是**本组织**最直接的竞争对手" | 定性结论 | `达文是**本组织**最直接的竞争对手 [^N]` |
| "预计 2030 年装船率达 80%" | 预测数据 | `预计 2030 年装船率达 80% [^N]` |
| "全球市场约 USD 11 亿" | 市场规模 | `全球市场约 USD 11 亿 [^N]` |

### 禁止行为

- ❌ 关键事实不带来源标注
- ❌ 使用裸 URL 代替 `[^N]` 格式
- ❌ 同一来源多次定义不同编号
- ❌ `[^N]` 编号跳跃
- ❌ 正文使用 `[^N]` 但未定义来源行（"幽灵引用"）
- ❌ 来源 URL 指向 404/失效链接
