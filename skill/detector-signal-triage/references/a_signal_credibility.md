### ①c 实证（2026-09-18·判据前提假设失效 → 误拒 **+ 连带损害**·T-24）

`write_guard._write_guarded_impl` 的 `verify_write` 判据为「文件内容 == 本次写入内容」——**该判据隐含一条从未被写下的环境假设：写入窗口内无第三方写该文件**。

2026-09-18 12:06:23，门禁写入 `drq/meta_patterns/META-104_超时膨胀反模式.json` 被判「校验失败」并**回滚**，致 META 判例登记未落地。

**归因过程（五条独立取证）**：

1. **隔离往返测试**（临时目录同名文件·零风险复刻写入-读取链）→ `str` / UTF-8 字节 / `newline=''` 三态**全绿** ⇒ 换行与编解码成因**证伪**（推翻初始怀疑方向）
2. **mtime 桶分布**：`drq/meta_patterns/` 下 **318 个源文件仅聚集 6 个时间桶**（含 **12:06** = 16 个）⇒ 存在**批量重写任务**，其窗口与前述失败时刻 **12:06:23 精确重叠**
3. **无并发重试**：同一路径 12:45 重试 `exit=0` **成功** ⇒ 反证「并发窗口」为唯一变量
4. **快照内容核对**：`versions/write_guard/<ts>/` 内唯一文件即该 META ⇒ 确证写入目标
5. **实时监测**：30 秒内 META 源文件**零变化**、仅 `index.json` 变化 ⇒ 批量窗口已结束（`index.json` 的周期写者归因为 Sidecar，但它**只写 index.json** ⇒ **与本案无因果·主动排除误挂因**）

**与 ①②③ 的本质区别**：①②③ 是**信号源自身机制坏**（崩在导入期／崩溃被洗白／崩在产出期）。本案**信号源全程正常运行、判据也按设计执行**——失效的是**判据所依赖、却从未被声明的前提**。故归 **①（假红·误杀）子型**，**不新增顶层态**。

**⚠️ ①c 的特有严重性：处置动作会连带损害**

普通假红的代价是「白修一次」；①c 的代价是「**失败后的补偿动作主动破坏他方数据**」——原实现在校验失败时**无条件** `shutil.copy2(snap, path)` 回滚，而快照是**本方写入之前**的状态 ⇒ 覆盖掉第三方在窗口内写下的合法内容 ⇒ **数据丢失**。

**修复双轨**（判据修正，而非加锁）：

- **前馈**：把 `verify` 移入**写租约保护单元**（原实现在 `os.replace` 后由 `finally` 立即释放租约、`verify` 在其后**无保护** ⇒ 两个同源进程即可互踩）
- **反馈**：**归因后择性回滚** —— 成因a（文件内容 == 写入前快照）保持原回滚语义（幂等无害）；成因b（内容 ∉ {本次, 写入前}，含文件已不存在）🛑 **禁止回滚**，并记 `concurrency_conflict` 事件
- **为何不加锁**：租约只互斥**走租约的写者**；批量 migration / 周期任务等外部写者不走租约 ⇒ 窗口**不可归零**，故取「归因 + 不越权覆盖」

**判据提炼（①c 判别问句）**：*「我的判据依赖了哪条我从没写下来的环境假设？——该假设失效时，我的**补偿动作**会不会伤到别人？」*

**可迁移性**：任何「**比对型守卫**」（写后校验 / 状态断言 / 幂等检查）都隐含「比对窗口内无第三方改动」假设；凡**失败后带补偿动作**（回滚 / 重放 / 覆盖）的守卫，均须按 ①c 检验补偿的**越权风险**。
