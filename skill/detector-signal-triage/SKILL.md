# 检测器红灯三分法

> **它解决什么**：🅑 检测器一红就改代码 —— 🅑 **而很多红灯不是代码的问题**。
> **它的立场**：🎯 **先判**报警性质**·🅑 再决定改哪儿** —— 🅑 否则会**误杀**。

---

## 一、🎯 三态

| 🎯 态 | 🎯 特征 | 🎯 处置 |
|:--|:--|:--|
| **模型缺陷** | 🅑 判据对·🅑 而对象**确实**不合格 | 🎯 **改对象** |
| **口径缺陷** | 🅑 对象没错·🅑 **而判据量的东西不对** | 🎯 **改判据** |
| **真问题** | 🅑 两者皆对·🅑 **而系统里确有毛病** | 🎯 **改系统** |

🛑 **判别捷径**：🅑 **问"如果我把对象改成完美的·🅑 这条判据会绿吗？"** ——
🅑 不会绿 ⇒ 🎯 **口径缺陷**。

---

## 二、🎯 五种常见"口径缺陷"

| 🎯 形 | 🅑 描述 |
|:--|:--|
| **判据之域太少** | 🅑 只扫了一部分 ⇒ 报的"缺口"是假的 |
| **判据之域太多** | 🅑 把不相干的东西也算进来 ⇒ 假红 |
| **输入不同源** | 🅑 判据吃的输入与真实环境不是一回事 ⇒ **恒绿** |
| **比较操作数不同源** | 🅑 "相等"判定两侧取自不同语义域 ⇒ **假漂移** |
| **端点语义错** | 🅑 区间端点把"上一份／本次自身"算进缺口 ⇒ **假缺口** |
