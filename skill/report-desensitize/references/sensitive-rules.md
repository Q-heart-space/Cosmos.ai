# 报告脱敏规则详细手册（sensitive-rules.md）

> 补充 `report-desensitize` 技能的详细脱敏规则与实例。来源：SKILL.md「分级速查」扩展。

## 核心原则

脱敏目标是「保留战略结论，清除内部数据」——让对外版本**结论可独立成立**，同时**不泄露任何可用于反推内部底牌的信息**。

## 四级规则详解

### 🔴 P0 · 必须删除（硬数据·泄露即事故）

| 类型 | 示例 | 处理 |
|:--|:--|:--|
| 内部财务数据 | 毛利率 32.7%、回款周期 45 天 | 整段删除，不替换 |
| ERP 产线数字 | 月产能 8000 台、良率 97.2% | 删除 |
| 博弈底牌 | 我方底线价、谈判筹码、让步顺序 | 删除 |
| 版本记录 | v2.3 内部迭代痕迹、TODO 标记 | 删除 |
| 内部客户名 | 未公开合作的客户全称 | 删除或改为「某头部客户」 |

### 🟡 P1 · 必须脱敏（精确数 → 定性描述）

| 类型 | 原文 | 脱敏后 |
|:--|:--|:--|
| 供板价/成本 | BOM 成本 ¥1,240 | 「成本可控」或「性价比区间」 |
| 薪资/人数 | 团队 23 人、研发 12 人 | 「精干研发团队」 |
| 客户精确数 | 20 家渠道商、95% 匹配 | 「多家渠道商」或「高匹配率」 |

### 🟢 P2 · 需要软化（措辞 → 商务中性）

| 原文 | 软化后 |
|:--|:--|
| 「竞品 X 技术落后」 | 「竞品 X 采用不同技术路线」 |
| 「客户投诉严重」 | 「客户反馈集中度较高」 |
| 博弈措辞 | 商务表述 |

### ⚪ P3 · 需要标注（待确认数据）

需确认的数据加 `⚠️【需XX确认】`，例如：`⚠️【需财务确认】`、`⚠️【需客户确认】`。

## 执行检查清单

1. P0 删除项是否全部清除（grep 财务/产能/底牌/版本关键词）？
2. P1 精确数是否全部转定性？
3. P2 负面措辞是否软化？
4. P3 待确认项是否标注？
5. 结论是否在删除后仍独立成立（不依赖被删数据）？
