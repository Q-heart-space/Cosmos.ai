# 多智能体团队编排

> **它解决什么**：🅑 多个 Agent 一起干活·🅑 **很容易变成"各干各的"** —— 🅑 或**互相等**。
> **它的立场**：🎯 **团队的价值在**交接**·🅑 而不在人数**。

---

## 一、🎯 四件必须先定

| 🎯 件 | 🎯 问什么 |
|:--|:--|
| **角色** | 🅑 每个成员**负责什么**·🅑 **不负责什么**（🅑 后者更重要） |
| **边界** | 🅑 谁**能改**哪些文件 —— 🛑 **两人同改一处 ⇒ 必冲突** |
| **交接** | 🅑 上游交什么给下游（🅑 **具体到件与字段**） |
| **收口** | 🅑 谁**判定完成**（🛑 不许"自己说自己done"） |

---

## 二、🎯 三条纪律

| 🛑 | 🎯 行 |
|:--|:--|
| 🛑 **写域不重叠** | 🅑 同一文件**同一时刻只有一个写者** |
| 🛑 **交接物须自洽** | 🅑 下游拿到就能用（🅑 不必回头问） |
| 🛑 **收口须第三方** | 🅑 **产出者不判自己的产出** |

## 四、边界 / Boundaries

- 🅑 本件是**编排方法** —— 🅑 与具体平台无关（🅑 任何支持多 Agent 的宿主皆可用）；
- 🅑 具体的**并行执行**归各宿主自己的调度（🅑 本件只管**结构与协议**）；
- 🅑 本件**不含**任何特定团队的成员名单。
