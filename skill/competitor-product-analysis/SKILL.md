# 竞品产品分析

> **定位**：竞品嵌入式硬件产品的标准化查询与分析方法论。确保每次竞品分析用同一套流程、同一组数据源、同一判定标准，避免凭记忆或直觉。
> **适用场景**：任何涉及竞品产品规格对比的任务——IPC、海事工控、嵌入式BOX、面板PC等。
> **核心教训（2026-07-02）**：Moxa 竞品遗漏暴露——仅查询英文产品页得出"无 IEC60945"结论，中文方案页有完整海事认证列表。根因是竞品信息收集缺少方法论。
> **v1.2 强化（2026-07-02）**：新增 §前置预检P0~P3，要求在输出竞品分析正文前完成四步验证——参数溯源、结论归属、交叉验证、准确性声明。预检不通过禁止进入正文。
> **v1.3 强化（2026-07-03）**：新增铁律CA-5（多列规格表逐行锁定）+ Step 1 多列子型号处理逻辑 + 禁止行为两条。触发场景：E7S系列 Q670 官网三列（E7S/E7DS/E7QS）并列时看错列，将 E7QS-Q670 的数据误读为 E7S-Q670 或反之。

## 🛑 前置预检（强制执行·数据输出前必须完成）

> **定位**：在输出竞品分析结果之前，先完成以下四步预检并输出验证结果。不通过预检的数据禁止进入正文。

### 预检步骤

#### P0 — 产品参数逐项溯源

逐产品输出，每项参数标注来源 URL + 抓取时间：

```
竞品：[名称·型号]
├─ CPU：[值] ← 来源：[URL] · 抓取：[时间]
├─ TDP：[值] ← 来源：[URL] · 抓取：[时间]
├─ 内存：[值] ← 来源：[URL] · 抓取：[时间]
├─ 网络：[值] ← 来源：[URL] · 抓取：[时间]
├─ 串口：[值] ← 来源：[URL] · 抓取：[时间]
├─ 认证列表：[逐项值] ← 来源：[URL] · 抓取：[时间]
└─ 温度：[值] ← 来源：[URL] · 抓取：[时间]
```

**不通过标准**：任何参数无来源 URL → 停止，补抓后再继续。
**时效规则（四级·不阻断·v1.5.0）**：①有更新日且 ≤365 天 → 正常使用；②有更新日且 >365 天 → 降级标注「时效较旧」；③无更新日 → 标注「时效不可判定」；④厂商官方页（一手源）→ 不设时效限制。以上均**不阻断**输出，仅在报告中标注时效状态。

#### P1 — 关键结论逐条归属

每条结论必须明确标注归属的竞品，禁止无主结论：

```
结论归属清单：
├─ [结论1] → 归属竞品：[名称]
├─ [结论2] → 归属竞品：[名称]
├─ [结论3] → 跨竞品比较 → 同时归属：[A vs B]
└─ ...
```

**不通过标准**：任何结论无法追溯到具体竞品 → **标记为"推论"而非"事实"**，或删除。

#### P2 — 交叉验证 5 项

| # | 检查项 | 方法 | 通过标准 |
|:--|:--|:--|:--|
| 1 | **归属正确性** | 逐条比对：每条规格/认证是否属于该竞品而非其他竞品 | 0 错位 |
| 2 | **数值一致性** | 同一竞品在不同节中引用的数据是否一致（如 CPU 在§4 和§8 都被引用） | 0 矛盾 |
| 3 | **认证归属** | 每条认证标注的"发证机构"是否与认证类型匹配（如 DNV 是船级社、IEC 是标准组织） | 0 概念性错误 |
| 4 | **来源多源覆盖** | 每个竞品是否至少覆盖 P0+P1 三层（产品页+PDF+方案页） | 100% 覆盖率 |
| 5 | **竞品间数据无串行** | 类似数值出现在不同竞品时，确认非复制粘贴错误（如两个竞品的 CPU 型号完全相同但确认确实是同一型号） | 0 串行 |

#### P3 — 准确性声明

输出前必须声明：

```
✅ P0参数溯源：N/N 通过（N项参数均有来源URL）
✅ P1结论归属：N/N 通过（N条结论均有归属竞品）
✅ P2交叉验证：5/5 通过（归属正确·数值一致·认证匹配·来源覆盖·无串行）
⚠️ 已知局限：[如有]未下载PDF/仅英文站未查中文站/[其他]
🛑 阻断项：[如有]X项参数无来源 / X条结论无归属 / X项认证归属错误
```

**阻断机制**：P0/P1/P2 中任一项不通过 → **禁止输出竞品分析正文**，先补数据。

## 输出落盘（🆕 v1.4·2026-08-24 对抗审计修复）

**🛑 根因**：v1.3 及以前，报告产生于对话即结束·无持久化——「已落地日志」承诺未兑现（2026-08-24 实证：研华 TPC-B620 报告声称落地但全空间零命中·假闭环·反模式#19 建成未接线变体）。**输出不落盘 = 知识不沉淀 = 下一次重复查询。**

**🛑 归位修正（v1.4.1·2026-08-24 跨空间边界）**：竞品对标报告是**业务空间产出**（业务报告）·不是 Q博士 治理资产——必须落在**调用方空间**（业务空间），禁止落 Q博士 的 research/ 对标目录（那是 Q博士 自我对标 Palantir 等·类别错位·铁律12 不越权·铁律BZ 内容归位）。

**强制步骤（报告输出后必须执行）**：

1. **落盘位置（调用方空间·自动感知）**：
   - 若在业务空间调用（如 IPC 日报）→ 落该空间竞品目录：`<调用方工作区根>/竞品对标/<厂商>_<型号>_竞品对标分析_YYYY-MM-DD.md`（🛑 v1.5.0：原硬编码样例已删除；pwd 自动感知方案已被 2026-09-15 实测证否，改用确定性规则）
   - 若调用方无竞品目录 → 在调用方空间新建 `<空间>/竞品对标/` 子目录（跟随该空间既有命名习惯）
   - **判断方法**：以当前工作目录/会话所在空间为准（`pwd`/项目根）·禁止硬编码 Q博士 路径
2. **头部字段**：版本/类型📊/日期/定位（对标分析报告）/来源（技能+触发词+业务空间）/依赖（官方产品页可反查 URL）/被依赖（业务日报后续引用）
3. **来源 URL 必须可反查**：官方产品页/新闻稿的具体 URL（非"advantech.com 产品页"模糊表述）——铁律 CA-1 精神：≥2 源需可验证
4. **认证数据标注**：认证项标注来源（官方 spec Certification 字段）·经外部多源验证后标"已外部验证"
5. **海事环境等级区分**：EN 60721-3-5 的 **5M3 = 道路车辆环境等级（非海事）**；海事环境对应 **EN 60721-3-6（6M 系列）**——竞品标注"宽温/抗振/加固"时须核查环境等级归属，防把道路车辆等级误读为海事认证（2026-08-20 研华 DLT-V8312 判例：英文官网未标海事认证·五源交叉验证确认真缺而非漏标·实际认证为 IP66+5M3 道路车辆级）
6. **口径修正**：官方"10+"类模糊数量·报告写"≥10"而非虚构精确数（2026-08-24 判例："12 种" vs 官方"10+"）

**验收**：报告文件真实存在于**调用方空间**竞品目录·来源 URL 可点击反查·认证标注来源·Q博士 空间无残留副本。

## 铁律（4 条）

| # | 铁律 | 违规后果 |
|:--|:--|:--|
| **铁律CA-1** | 竞品信息必须**≥2 个信息源交叉验证**（产品页 + 方案页/数据手册/新闻页），单源判断 = 无效 | 单一数据源可能遗漏认证/定位信息（Moxa 教训） |
| **铁律CA-2** | 竞品查询必须**多语言站交叉验证**——有原始国语言站必查原始国，再查英文全球站 | 英文站面向通用市场、原始国站面向专业市场，认证列表可能不一致（Moxa 教训） |
| **铁律CA-3** | 每条认证/规格数据**必须标注来源 URL 和抓取时间** | 不可溯源的数据影响结论可信度 |
| **铁律CA-4** | **多源数据不一致时取优先级最高的版本**（按 §版本优先级规则），并标注差异 | 不标注差异会导致结论被质疑 |
| **铁律CA-5** | **多列规格表必须逐行锁定**——官网产品页有多个子型号并列时，必须先建"型号→列→数据行"对应清单，截图标注目标列，再逐行读取。**严禁跨列串读或在多列间混淆参数。** | E7S/E7DS/E7QS 三列并列 → 看错列 → 67.7mm 写到 159.5mm 型号（2026-07-03 教训） |

## 信息源优先级规则

### A. 语言版本优先级（铁律CA-2 细化）

| 优先级 | 语言 | 说明 |
|:--|:--|:--|
| **P0（最权威）** | 原始国/原始语言站 | 厂商母语站，通常最先更新、最完整。如 Hatteland → `hattelandtechnology.com`（英文即原始）；Beijer → `beijerelectronics.se`（瑞典语优先）；Kontron → `kontron.com`（德语/英文） |
| P1 | 英文全球站（`.com`） | 国际版，面向全球客户，通用规格准确但行业认证可能不全 |
| P2 | 中文站（`.com.cn` / `.cn`） | 中国版，面向中国客户，解决方案页认证列表可能比英文产品页更详细（Moxa 案例） |
| P3 | 其他区域站（`.jp` / `.kr` / `.de`） | 特定市场版本，仅作补充参考 |

**适用规则**：
- 原始国 = 英文时（如 Hatteland、Winmate、Vecow），P0 = P1，以英文站为准
- 原始国 ≠ 英文时（如 Beijer/瑞典、Kontron/奥地利），P0 为原始语言站
- **P2 中文站可能有 P0/P1 没有的认证数据**——Moxa 案例：中文方案页有完整 8 项海事认证，英文产品页只有 4 项

### B. 信息模块优先级（多源覆盖）

| 优先级 | 信息模块 | 包含数据 | 典型 URL 模式 |
|:--|:--|:--|:--|
| **P0 规格** | 产品页（HTML） | CPU/TDP/内存/接口/尺寸/温度 | `/products/xxx` 或 `/view_product?id=xxx` |
| **P0 认证** | 数据手册（PDF） | 完整规格 + 认证列表 + 环境测试数据 | `/download/datasheet/xxx.pdf` |
| **P1 定位** | 行业方案页 | 应用场景、目标市场、认证合规声明 | `/solutions/industry-focus/marine` |
| **P1 时效** | 新闻/公告页 | 新品发布、认证获取、EOL 通知 | `/news/` `/media/news/` `/press/` |
| **P2 验证** | 案例研究页 | 真实部署场景、客户名称 | `/case-studies/` `/customers/` |
| **P2 状态** | 下载/资源中心 | 固件更新、生命周期声明、认证证书 PDF | `/download/` `/resources/` `/support/` |
| **P3 动态** | 展会专题页 | CES/Embedded World/Marintec 新品发布 | 站内搜索展会名称 |
| **P3 动态** | YouTube/视频 | 产品演示、拆解视频 | youtube.com/@厂商名 |

**适用规则**：
- 规格数据：PDF 数据手册 > HTML 产品页
- 认证状态：认证证书 PDF > 方案页声明 > 产品页标签
- 产品时效：新闻公告页的发布日期 > 产品页的"最后更新"日期
- **至少覆盖 P0+P1 三层（产品页+数据手册+方案页）才算完整**

### C. 数据冲突裁决规则

当不同信息源的数据不一致时，按以下顺序裁决：

1. **认证数据冲突**：独立认证证书 PDF（如 EN60945 Certificate PDF）> 方案页声明 > 产品页标签
   - 原因：证书 PDF 有发证机构签章和有效期，是法律文件
2. **规格数据冲突**：最新更新日期（新闻/产品页最后更新）> 旧版本
   - 原因：产品可能在迭代中升级了规格
3. **语言版本冲突**：原始国站 > 英文全球站 > 其他区域站
   - 原因：母语站最新最准确
4. **裁决后处理**：报告中必须标注"X 站显示 A，Y 站显示 B，以 X 站（P0）为准"，不能不说明就取舍

### 非中英文站点的处理策略

当竞品网站不提供英文或中文版本时（如日本 ClassNK、韩国 KR、法国 BV 的原站）：

| 场景 | 策略 | 工具 |
|:--|:--|:--|
| **有英文子站** | 以英文站为主信息源，原站为补充 | WebFetch 双站 |
| **仅原始语言**（日/韩/法/德） | 用原始站 WebFetch，prompt 中要求提取数字/规格/认证名称（非依赖完整句子理解） | WebFetch + 提取关键术语 |
| **认证 PDF 为通用格式** | 认证证书 PDF 通常用英文标准术语，原始语言仅附加页 | 优先下载英文版 PDF |
| **非拉丁字符站点**（日/韩/阿拉伯）| 浏览器截图 + 视觉识别关键页面结构 | agent-browser snapshot |

### 新增竞品时

1. 先在 `industry-intelligence-sourcebook` 对应 JSON 中注册（公司名+URL+分类）
2. 再用 `competitor-product-analysis` 七步路径执行查询
3. 禁止跳过 sourcebook 注册直接查询——否则下次换人/换会话时找不到入口

| 定位 | 判定标准 | 示例 | 是否直接竞品 |
|:--|:--|:--|:--|

### 🆕 多源交叉验证规则（2026-07-03 新增·IPC v5.3 复盘驱动）

> ⚠️ **来源**：IPC v5.3 复盘·模式4——竞品信息查询仅查英文产品页，遗漏中文方案页中的关键差异（Moxa 认证状态不同）。

**强制规则**：每个竞品/产品的关键数据点，必须同时验证至少 2 个来源：
1. **产品页**（英文官网产品详情页）
2. **方案页/白皮书**（中文或英文）
3. **区域站**（如中国区 vs 全球站可能有不同产品配置）
4. **认证页**（UL/CE/FCC/IEC60945 等认证数据库）

**触发条件**：任何涉及竞品规格、认证、价格、出货量的数据引用。

**审计点**：若分析报告中的竞品数据仅标注 1 个来源 → 标记为"来源不足"，触发补充查询。

## 盲区与自审
- 本技能的已知盲区：本技能只提供查询方法论，不内置任何竞品数据——竞品清单与 URL 依赖 industry-intelligence-sourcebook，sourcebook 未收录的竞品本技能无从查起；无法覆盖需登录/付费墙/未公开的厂商资料；查询能力依赖 WebFetch/agent-browser 工具可达性，站点反爬或 PDF 无法解析时数据必然缺失。
- 自审方式：P0 参数溯源出现"无来源 URL"或 P2 来源覆盖率 <100% 时，即说明存在未覆盖的信息源，应补抓而非强行输出结论；当竞品清单里找不到目标厂商时，检查 sourcebook 是否过时需更新。
