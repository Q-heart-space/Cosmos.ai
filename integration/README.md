# 对外公开库 · `integration/` 域

**接收方问题**：🎯 **我要接进我的系统**

**状态**：🟡 域已建（契约预留）·内容待产。

## 一、这一域收什么

🎯 **可安装 / 可接入的集成单元** —— 其**形态**（六形态之三类）退为 **manifest 字段**：

```json
{ "form": "mcp" | "plugin" | "automation" }
```

| 形态 | 现状 | 解锁条件 |
|:--|:--|:--|
| `Plugin` | `NOT_READY` | 待**通用宿主 manifest**（而非绑单一宿主） |
| `Connector` | `NOT_READY` | 待**凭据外置**（使用者自填·零私有凭据即可装载） |
| `Automation` | `NOT_READY` | 待**模板变量化**（`cwd`/账户与定义解耦） |

## 二、进域判据（🆑 双轴合取·取自 §5.3）

| 轴 | 判据 |
|:--|:--|
| **产物轴** | 是否存在**与实例无关的可分发定义**（manifest / schema），使接收方能**重建等价实例**？ |
| **依赖轴** | 重建依赖是否**全为公开可得 / 标准协议**？私有项是否已**外置为使用者自填配置**？ |

**两道防刷分测试**：① **干净环境重建**（零私有凭据/路径/账户下可装载并产生一次可验证行为）② **实例剥离**（删本组织实例后定义仍完整）。

## 三、🛑 为什么本域叫 `integration/` 而不叫 `plugin/`

域按「**接收方的问题**」分，🛑 **不按「对象形态」分**（§5.3 🔑 判据）。

🅑 按形态建域 = 把**对象维**灌入**域维** ⇒ **混轴** ⇒ 触发 §5.3 之**可失败判据**（期望 0 命中）。
