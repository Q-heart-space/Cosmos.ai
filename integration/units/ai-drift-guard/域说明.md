# `ai-drift-guard` —— DSH 宿主插件（`form: plugin`）

> **域**：`integration/`（接收方问题＝「**我要接进我的系统**」）
> **形态**：`form: plugin`（六形态之 `Plugin`·🅑 按 §5.3 **退为 manifest 字段**·🛑 不另建 `plugin/` 域）
> **来源支**：🎯 **`host-adapters`**（该支自陈＝「**宿主接入产物**」·「**不是能力本体**」）
> **来源路径**：`dsh/plugins/ai-drift-guard/`
> **许可**：MIT（`package.json` 之 `license`）

## 一、它是什么

把 **AI-Drift-Guard** 协议接进 **DeepSeek Harness** 的**宿主绑定产物** ——
让 S5／S4 信号成为**运行期真实门**（🅑 而非仅提示词层自检）。

## 二、为什么它在 `integration/` 而不在 `skill/`

🛑 **它不是能力本体**（能力本体在 `capabilities` 分支之 `ai-drift-guard` 技能）。
🎯 它是**让该能力在某平台上跑起来**的那一层 —— 即 §5.3 之**双轴**皆过者：

| 轴 | 判据 | 本件之实 |
|---|---|---|
| **产物轴** | 有**与实例无关之可分发定义**（manifest／schema）？ | ✅ `cordis.patch.yml`（bundle patch）＋ `package.json`（`main` / `exports`） |
| **依赖轴** | 重建依赖**全为公开可得**？私有项**外置**？ | ✅ `lib/core.mjs` 系技能核之**逐行副本**（自闭环）·**无平台资产标记** |

## 三、目录

```
ai-drift-guard/
├── package.json          # 分发定义（name / version / main / exports / license / dsh.bundle）
├── cordis.patch.yml      # 宿主装载补丁（插件真正被加载靠它）
├── lib/index.js          # DSH **对接层**
├── lib/core.mjs          # 规则核（技能核之副本·🅑 行尾按各面规范）
├── README.md             # 宿主侧说明
└── PROVENANCE.md         # 来源与边界（🅑 含一处就地订正）
```

## 四、怎么接进你的系统

1. 读 `package.json` 之 `dsh.bundle.patch` ⇒ 指向 `cordis.patch.yml`
2. 按你的宿主之插件装载方式应用该 patch
3. 规则核在 `lib/core.mjs`·🛑 **不需要**原平台的任何私有依赖

## 五、诚实标注（🅑 取自源件 `PROVENANCE.md`）
