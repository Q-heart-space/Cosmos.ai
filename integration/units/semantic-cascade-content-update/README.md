# semantic-cascade-content-update — 交付物语义级联与内容级更新单元

> 版本：v1.0.0 · 形态：`integration` · `form: protocol`
> 面向使用者的问题：**一个规则、字段、流程或交付物发生变化后，怎样把真正受影响的内容同步完，并证明没有漏？**

## 它解决什么问题

这不是某个企业的业务结论，也不是 Q博士 的运行时副本。它是一套可迁移的**变更协议**：

```
源变更 → 语义影响分析 → 受控提案 → 内容/行为/接线更新
        → 写后回读 → 消费者确认 → 可回滚收据
```

“改了一个文件”不等于“级联完成”。只有拿到消费者确认和回滚信息，才可以把状态标为 `READY`；缺任一环节就保持 `UNKNOWN` 或 `NOT_READY`。

## 外部使用者怎么接

1. 你的系统产生一条 `change-event.json`，只描述**变更对象、原因、范围和前后摘要**，不放业务原文、凭据或机器绝对路径。
2. 你的影响分析器输出 `cascade-plan`，至少列出语义单元、目标文件/字段、变更类型和验收方式。
3. 高风险变更先人工批准；默认只做 dry-run。写入方必须提供授权范围，并在写入前锁定源版本摘要。
4. 每个真实消费者完成自己的检查后，回填 `consumer-receipt.json`。消费者不回执，发布方不得报“已同步”。
5. 失败时按 `rollback_ref` 回退或标记不可回退，并保留失败收据；禁止静默覆盖。

## 交付内容

| 文件 | 用途 |
|---|---|
| `schema/change-event.schema.json` | 变更事件的机器合同 |
| `schema/cascade-plan.schema.json` | 影响面、提案、风险与回滚合同 |
| `schema/consumer-receipt.schema.json` | 消费者回读/验收合同 |
| `examples/` | 可复制的最小正例；不含任何组织私有数据 |
| `manifest.json` | 版本、外置配置和验收声明 |
| `PROVENANCE.md` | 来源、边界和未宣称事项 |

## 能复用与不能复用

- 可复用：事件字段、七环顺序、`dry-run` 默认值、前后摘要、消费者回执、回滚语义。
- 需要接入方实现：自己的语义索引、文件/数据库写入器、测试命令、审批系统和存储位置。
- 不随件提供：Q博士 内部治理文件、客户/ERP/CRM 数据、会话回执、密钥、宿主绝对路径。

## 状态声明

本单元已完成**合同和样例自证**，属于 `contract_ready`。它不声称你的系统已经接入或已经完成跨平台行为等价；接入后必须用真实消费者回执重新验收。
